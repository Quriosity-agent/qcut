# 独立美体 · 图片版

本版可以导入一张照片，用**长腿、瘦腰、小头、整体瘦身、瘦手臂、肩宽、直角肩、天鹅颈、胯宽、胸围、大腿粗细、小腿粗细**十二个滑杆调整身体比例，也支持**背景保护、手动局部拖动修形**，再以半图擦拭检查实际结果、导出 PNG。每次处理都从导入时保存的原图计算，不会把上一次结果继续叠加。

**macOS 默认继续使用 Metal；Windows、Linux 使用新增的 CPU / ONNX 后端。** 完整便携包也可在 Mac 上显式使用 CPU。安装、模型交付和实际平台测试见 [多平台图片版说明](PORTABLE.md)。本版处理单人、正立的静态照片；尚不是视频编辑器，也不是实时拖动出图。

## 原有 Mac 版启动

需要 macOS、可用的 Metal、[uv](https://docs.astral.sh/uv/getting-started/installation/) 和 Xcode 命令行工具。缺少命令行工具时先在终端运行：

```sh
xcode-select --install
```

在项目根目录执行一次安装：

```sh
sh body/setup.sh
```

安装脚本使用 `body/.venv` 建立独立 Python 3.12 环境，安装 `body/requirements.txt` 中的依赖，并核验算法源码及模型。首次安装依赖需要网络；已有完整 uv 缓存时可用 `BODY_OFFLINE=1 sh body/setup.sh` 离线安装。安装脚本不会下载或替换模型，缺少私有模型时会停止并提示。

安装完成后，在 Finder 打开 `body` 文件夹，双击 **「启动独立美体.command」**。也可以从项目根目录执行：

```sh
sh 'body/启动独立美体.command'
```

默认打开 `http://127.0.0.1:5270/`。保持启动终端打开；按 **Control-C** 停止服务。端口被占用时可指定另一个端口：

```sh
BODY_PORT=5271 body/.venv/bin/python body/launch.py
```

只启动服务、不自动打开浏览器：

```sh
body/.venv/bin/python body/server.py --port 5270
```

## 修一张照片

1. 点击「选择一张照片」，打开 PNG、JPEG、WebP 等静态图片。原图会立即显示，准备完成后可调整参数。
2. 调整下表中的项目，也可以直接输入数值。数值代表算法强度，不是厘米、围度测量或身体尺寸变化百分比；肩宽、胯宽、胸围、大腿粗细、小腿粗细以 **0 为中央原始状态**，支持负值。
3. 点击「应用调整」。首次非零处理可能编译自写的 Metal 程序，需要多等一会儿。计算期间可以继续改参数，再次点击应用会保留最新一组待处理设置，不会同时运行多份处理。
4. 在「半图对比」中，左边为原图、右边为实际处理结果，默认分界在 50%。拖动照片中的分界或下方「对比位置」滑杆检查同一位置；滑杆也支持键盘方向键。可以切换「原图」「实际结果」查看完整画面。
5. 确认状态后，点击「下载实际 PNG」。参数或照片一旦更改，旧结果的下载会立即失效，需要重新应用，避免导出过期结果。

| 项目 | 公开参数 | 整数范围 | 调整方向 |
| --- | --- | --- | --- |
| 长腿 | `StretchLeg` | 0–100 | 增强拉长 |
| 瘦腰 | `SlimWaist` | 0–100 | 增强收腰 |
| 小头 | `SmallHead` | 0–100 | 增强缩小 |
| 整体瘦身 | `SlimBody` | 0–100 | 增强整体收缩 |
| 瘦手臂 | `SlimArm` | 0–100 | 增强手臂收缩 |
| 肩宽 | `ShoulderWidth` | -50–50 | 负值收窄，正值加宽 |
| 直角肩 | `OrthoShoulder` | 0–100 | 修饰肩线 |
| 天鹅颈 | `SwanNeck` | 0–100 | 修饰颈肩线，不保证精确颈长 |
| 胯宽 | `HipWidth` | -50–50 | 负值收窄，正值加宽 |
| 胸围 | `BustSize` | -50–50 | 负值缩小，正值增大 |
| 大腿粗细 | `ThighWidth` | -50–50 | 负值收窄，正值加宽 |
| 小腿粗细 | `CalfWidth` | -50–50 | 负值收窄，正值加宽 |

「全部归零」会把十二项设为 0、清空手动笔画并关闭背景保护，重新显示原图；点击应用后可生成与归一化原图一致的 PNG。天然身体左右不对称也会影响半图观感，判断时请移动分界线查看同一位置。肩宽、胯宽、胸围正负两侧的系数不同，绝对值相同不表示变化幅度相同。

整体瘦身的范围比瘦腰更广，两者可以组合，也可能加强同一区域的收缩。瘦手臂依赖可见的肩、肘等关节；弯肘、手贴身体或遮挡时可能只处理可用的一侧。不能仅凭非零强度就认定生效，页面按对应网格移动和输出像素证据显示结果。

肩宽、直角肩需要相应肩肘／颈点；天鹅颈还依赖双肩及匹配人脸。胯宽依赖胯部关节，胸围依赖躯干朝向和双肩，侧身或裁切可能导致单侧、不对称或不可用。前十项公开参数在包装层映射到固定引擎名称，不把内部 `Test` 名称显示给用户。旧三项／五项／十项请求仍可使用，缺省的新参数保持零。

大腿粗细、小腿粗细是本项目新增的局部腿部控制，不是另一个长腿滑杆。大腿需要左右两侧髋点及膝点，小腿需要左右两侧膝点及踝点；关节置信度均须至少 0.2，骨段不能过短、交叉或明显偏离正立姿态。任何一侧条件不足时，对应项目整体不可用，不会悄悄只修一条腿。两项不依赖人脸；粗检测人体数量不是恰好 1 时，腿部扩展会停用。它们改变的是局部图像轮廓，不测量真实腿围。

## 背景保护与手动局部修形

背景保护默认关闭。勾选后，使用本机 **Apple Vision** 人物分割，自动滑杆与手动笔画共用最终网格；照片只采样一次，蒙版按同一网格变形。原始与变形人物蒙版的并集留出少量过渡，再与原图合成。收据记录保护像素数、蒙版哈希及 `changedProtectedPixels=0`。这是远离轮廓的背景保留，不是背景修复或补全。没有可靠人物蒙版、系统分割失败时，启用保护的非零调整会明确失败。

展开「手动局部修形工具」，在独立的原图面板拖动；圆表示笔刷范围，箭头表示方向。也可输入起点及位移，画布获得焦点后用方向键调位移、Enter 添加、Esc 取消拖动。半径是照片短边的 2%–30%，单笔位移不超过半径的一半，最多保留 32 笔；支持撤销最后一笔和清空。收起工具不清空已记录笔画。点击「应用调整」后才生成实际结果，改动或撤销会立即使旧下载失效。

笔画坐标是原图左上角归一化坐标；手动几何在自动身形调整后依次执行，自动滑杆改变后，原坐标处的身体部位可能移动。开启保护时，完全落在原始／自动变形人物范围之外的笔画会跳过；连续拖动把轮廓移出该范围时，后续拖动也可能保守停用。网格边界固定；可能导致三角形翻折的拖动会减小或停用并显示状态。关闭背景保护后，手动工具不依赖人体关键点，可作用于近景或其他图片区域。

HTTP `/api/render` 可选字段：

```json
{
  "photoId": "导入接口返回的编号",
  "values": {"SlimWaist": 60},
  "edits": {
    "backgroundProtection": true,
    "strokes": [{"start": [0.55, 0.45], "end": [0.52, 0.45], "radius": 0.15}]
  }
}
```

CLI 同样支持 `--edits` JSON；不传该字段时保留旧控制请求和渲染路径。页面、响应和收据包含相同笔画，按实际应用／部分应用／未应用反馈，不用“请求成功”代替出图成功。

人物蒙版依赖 macOS 系统自带的 Apple Vision 模型，首次调用编译自写的 `person_mask.swift`，缓存仅写入 `body/.state/cache/`；未新增私有模型文件或厂商效果动态库。背景保护也尚未移植到 Windows/Linux。固定的 107 份引擎源码及 5 项模型保持原样。

## 结果状态

- **调整已应用**：本次启用的项目均有对应部位形变证据，且输出像素发生变化。
- **部分调整生效**：只有部分启用项目生效，逐项说明会列出没有应用的部位。可下载的 PNG 只包含实际发生的处理。
- **未应用 · 正在显示原图**：当前照片没有可应用的对应部位，例如膝盖被衣物遮挡、身体检测不完整。界面保留原图并显示原因，不把它标成成功美体，也不提供结果下载。
- **输出保留原图**：参数为零的正常归零结果，不表示身体已发生修改。
- **处理未完成**：模型、运行环境、请求或处理发生错误。先按提示修复，再重新应用。

## 图片与质量范围

- 上传文件上限 **20 MiB（20,971,520 字节）**；只接受单张静态图，不接受动画图片。
- 导入时按 EXIF 方向转正；透明区域会合成白色背景。引擎接收的是不透明图片。
- 超过预算时等比缩小：最长边不超过 **4096**，总像素不超过 **8,294,400**。宽、高均需至少 32 像素，原文件解码超过 8000 万像素会拒绝。极端狭长画幅缩小后短边不足时也会提示裁剪。
- 导出宽高与**界面显示的归一化原图**一致；不会恢复被导入缩小的原始分辨率，也不承诺保留原文件的 EXIF 或色彩元数据。
- 优先使用身体轮廓清楚、关节可见的单人正立照片。侧身、严重遮挡、宽松衣物和多人画面不属于本版完整验收范围；无法应用的部位会明确提示。
- 十二项当前都依赖人体关键点，包括小头；仅有人脸的近景、半身照片也可能均不可用，不会自动切换到另一套捏脸算法。部分半身照可以获得上身关键点；这不保证其他半身照片也可用。大腿、小腿的可用性分别判断，缺少踝点时小腿可能不可用，即使大腿可调整。
- 可开启人物蒙版背景保护：保留原始及变形人物轮廓并集的窄过渡区域以外的原图像素。紧邻轮廓、收窄后露出的背景及人物衣物仍可能变形；不重建被身体遮挡的背景。识别失败会拒绝交付，不会悄悄关闭保护。
- 输出画幅固定，高强度长腿可能使脚部等肢体超出画面；请从较低强度开始，检查完整结果后再导出。
- 处理耗时随照片、首次编译和机器负载变化；拖动滑杆只修改待处理参数，**需点击应用出图**。其他 Mac 硬件仍需单独实测。

## 独立运行与模型来源

本版固定采用 QCut 提交 **`7bd5ceacc996b924c25563f430651dd1046d6ce0`** 中的 **107 份算法源码及必要资源**，清单在 `engine-source-manifest.json`。当前入口是静态照片路径，保留其同图稳定更新及网格规则；并未把最新视频时序对拍结果移作照片路径的验收结论。

新增的 `leg_shape.py`、`leg_render.py` 在固定引擎之外实现大腿／小腿粗细，沿用既有身体关键点模型，没有修改这 107 份固定源码或增加模型。两项属于自研扩展，**不宣称原生同名功能、原生参数或像素级对齐**。

运行时自行执行推理、状态、几何和 Metal 绘制，**不需要启动 QCut，也不调用 QCut 或厂商效果 dylib**。源码与模型按清单核验；结果收据记录输入、输出身份和运行来源。

感知使用 `../runtime/body/research/` 中 **5 项既有私有模型／辅助数据，共 7,431,877 字节**：

| 文件 | 用途 |
| --- | --- |
| `body-skeleton-v1.npz` | 身体关键点网络 |
| `face-detector-dynamic.onnx` | 人脸检测 |
| `face-align-120.onnx` | 人脸对齐／跟踪 |
| `face-align-160.onnx` | 人脸初始化 |
| `alignment-assets-v1.npz` | 对齐辅助数据 |

这些是原有私有资产的独立副本，**不是自行训练的权重**；复制或转换格式不改变来源。资产大小与 SHA-256 在 `asset-manifest.json`，模型及本机运行数据不进入 Git。

美体使用独立的 `body/.venv`、`runtime/body/` 和 `body/.state/`。上传原图、实际结果和收据保存在 `body/.state/`，不会修改原始照片文件，也不改动现有独立美颜的虚拟环境或运行资源。首次生成的自写 Metal 编译缓存保留在美体自己的运行目录。

## 多图矩阵与半图图库

`verify_matrix.py` 可重复验证多张本机照片，分别处理十二个控制的单项、双向极值及分阶段组合，并在前后各生成一次归零输出。它逐项检查照片及参数身份、尺寸、透明度、PNG/RGBA哈希、下载与显示一致、原图保留和逐部位形变证据，保存收据并生成可离线打开的中文擦拭图库。

先准备本机 JSON 清单，图片使用真实绝对路径。以下期望只是格式示例，应按照片可见部位和独立验收结果填写；不能直接假定所有照片都生效：

```json
{
  "version": 1,
  "entries": [{
    "id": "upright-a",
    "image": "/absolute/full-body-photo.png",
    "label": "正立全身照 A",
    "sourceKind": "real-photo",
    "subjectId": "person-a",
    "expectations": {
      "long-leg-100": "applied",
      "combined-extreme": {
        "status": "partial",
        "appliedControls": ["SlimWaist", "SmallHead"]
      }
    }
  }]
}
```

```sh
body/.venv/bin/python -B body/verify_matrix.py \
  --manifest /absolute/body-matrix.json \
  --output /absolute/new-body-matrix-report \
  --base http://127.0.0.1:5270
```

输出目录须尚不存在。打开其中的 `index.html` 查看逐项半图和状态，`acceptance.json` 保存完整核验。期望可用 `applied`、`partial`、`unavailable`；部分生效可声明准确的 `appliedControls`。未填写期望的非零项仍会实跑，但只记录为待确认，不能计为通过。退出码 **0** 表示全部符合声明及交付检查，**2** 表示尚有未声明期望的观察项，**1** 表示请求、交付证据或期望不匹配失败。任何自动检查都不等于自然度或所有姿态验收。

矩阵现有 28 个用例：保留十项阶段的 22 项，新增大腿／小腿正负极值、双腿部收窄组合和十二项中档组合。旧 `combined-extreme` 仍只启用原三项，`combined-five-extreme` 仍只启用原五项；`combined-ten-extreme` 也仍只启用原十项，腿部新项保持零。十二项中档使用独立的 `combined-twelve-moderate`。旧清单未声明新增用例时，这些项目计为待确认。

同一个人的多帧、补边图和 EXIF 派生图请保留同一 `subjectId`。`sourceKind` 区分真人照片、真人视频帧、合成参考和构造负例，`notes`、`source`、`provenance` 可记录构造及来源。照片、报告和收据仍只保存在本机忽略目录。

新增 `Independent body no-model contracts` 工作流在 Ubuntu、Windows、macOS 执行上传、API、启动、异常清理、矩阵验证器和前端状态测试，不读取私有模型。这个 CI 只验证应用契约，**不代表 Windows/Linux 的非零美体渲染已经可用**；真实模型和 Metal 出图仍单独在 Mac 验收。

渲染异常或取消会删除本次半成品 PNG 和收据；超时和正常关闭服务也会清理本次独立渲染进程组，等待在途请求回滚后退出。启动器会确认本次新服务的实例身份，端口上的旧服务不会被误报为启动成功。

## 尚未完成的图片美体能力

- **关键点定位修正**：局部手动修形已实现，但尚不能直接纠正髋、膝、踝等识别关键点。
- **多人目标选择**：尚不能指定合照中的编辑对象；腿部扩展遇到多个粗检测人体时停用。
- **背景重建与衣物保护**：人物分割及外围背景保留已实现；轮廓附近、收窄后露出的背景仍可能变形，衣物也随人物移动。尚无背景重建或衣物独立保护。
- **体态与腿型矫正**：腿粗细与长腿已分开控制，但尚无独立的腿型拉直、姿势矫正或躯干比例控制。
- **脚部与画幅保护**：尚无保留脚部的自动补边／画幅扩展；高强度长腿仍需检查脚部是否出界。
- **更多照片与平台**：严重遮挡、侧身和各种服装／体型仍缺少充分验收；Windows／Linux 非零出图及实时拖动预览尚未实现。本阶段继续只针对静态图片。
