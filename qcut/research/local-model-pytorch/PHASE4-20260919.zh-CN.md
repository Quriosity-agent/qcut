### 没有隐藏失败

- GRU：117 个不同采样帧、240 次时序推理，三个循环状态共 720/720 比较通过，但最终概率只有 18/240 通过。四像素反例显示上游微小差异跨过倒数估计桶边界，整体仍失败，统一入口继续拒绝。

## ONNX 执行协议

`onnx_export.py` 导出固定形状图，`onnx_infer.py` 只依赖 NumPy + ONNX Runtime，不导入 PyTorch、CoreML 或厂商库。
每份导出包含单文件 `model.onnx`、`contract.json`、`report.json` 和四组可回放 NPZ。

1. 先通过已有严格加载器读取验证过的 PT，不支持的候选不能导出为已验证包。
2. 使用标准 ONNX opset 18；不携带外部 tensor 文件或自定义厂商算子。
3. 合同固定名称、dtype、shape、模型 SHA-256 和源包 SHA；路径越界、软链接、超限文件、非有限值和不匹配 schema 均拒绝。
4. 验证原输入、零值、两个固定随机留出集的全部终端输出，失败合同默认不能加载。
5. 固定 CPUExecutionProvider，关闭图优化以保留已观察的数值行为；INT16 要求逐值一致，不用浮点容差掩盖一位误差。
6. NPZ 不启用 pickle，检查成员重复、类型、有限值与解压总大小；输出必须是新文件。

旧式 TorchScript exporter 在这里用于已审计、固定形状的小范围研究图，不宣称任意 PyTorch 程序都可自动转换。
警告存入私有 `export-warnings.json`。依赖数据的 Python 分支可能被追踪冻结，因此额外用实际错误追踪模型验证失败门槛。
没有动态尺寸、CUDA、MPS、TensorRT 或自动优化后数值一致的承诺。

### 跟踪和 OCR 的特殊数值实现

- 跟踪三个定点子网改用 Unfold + Double MatMul，保留 INT32 溢出回绕、舍入、饱和及多输入指数对齐。不能简单转成普通 FP32 Conv。
- 跟踪头的指数/倒数估计用标准 ONNX 算术表达位级语义；超过百万个输入验证指数实现，额外覆盖倒数桶、标量尾部和实际 ORT 运算。
- 四个跟踪子网再比 52 组冻结原生输入输出，全部逐值一致；这不是新运行 52 次原生 oracle。
- OCR 保留顺序 FMA、顺序空间归约和两次倒数细化，不替换为通用 Conv/ReduceSum/Sigmoid。实际图含 17,514 个顶层节点，CPU 性能尚未优化，不作为默认产品实现。

导出四组之外，三份视觉网络全部 54 组冻结样本、OCR 全部 20 组冻结样本均再次执行 ONNX，分别回比原生和 PT 完整输出，都在固定门槛内通过。
OCR 的 argmax 全部一致只是附加诊断，不代替 26,974,720 个 logits 元素的比较，也不等于文字识别正确率。

## 媒体 E2E

详见[媒体 E2E 记录](pipeline-e2e-phase4.zh-CN.md)。实际链路包含：

```text
参考视频 -> FFprobe -> FFmpeg 解码 -> 显式前处理 -> PT/ORT
 -> 全部网络输出检查 -> 掩膜/热图/特征诊断可视化
 -> H.264 MP4 -> FFprobe + 全量解码 -> PNG 抽帧检查
 -> 独立重放 -> seek/reset -> 跨后端全部输出比较
```

常规矩阵 **56/56 条通过**，28 条 PyTorch、28 条 ONNX，覆盖 14 个可直接接视频的包及两段参考素材。
共 **1,200 主帧 + 1,200 独立重放帧**，696 组跨后端完整输出比较通过，最大绝对误差 `1.0014e-4`，仍满足固定混合容差。

另外 4 条压力用例通过：video-object 两个后端各运行 60 秒 / 240 帧连续反馈，以及从第 30 秒跳转、重置后的 8 帧回放。
增加 **496 主帧 + 496 独立重放帧**，另有处理到第 35 帧时 SIGTERM 取消、退出码 130 的实测。
压力样本为原短片循环生成的 60 秒素材，非 60 秒独立新画面；采样进程树和子进程峰值均低于设定的 2 GiB，最大约 **1.35 GiB**。
这是有界研究批次，不承诺恒定内存或生产性能，后续产品需流式解码和内存优化。

常规与压力合计 **60 条成功媒体链、60 个 MP4、60 张 PNG**；累计 **1,696 + 1,696 帧、944 组跨后端输出对照**。初始调试预跑和失败重试不计入这些数量。

这是模型媒体链 E2E，**不是 QCut 编辑器 E2E，也不是视觉效果质量验收**。
两段输入包括真人舞蹈和生成画面参考；重复/循环素材用于状态压力测试时另行标记，不能当成新增独立素材。
截图是实际输出视频的抽帧，不是编辑器 UI 截图。已人工打开人物分割、时序对象分割、OCR 检测等 PNG 检查。

分类/CLIP 特征热图只用于观察模型输出；OCR 概率图未做框恢复或文字识别；法线坐标系和关键点回投均未完成产品语义验证。
媒体工具还使用 Torch 做前处理/对照，不把整个视频工具宣称为无 Torch；只有独立 ONNX tensor runner 已在无 Torch Linux 执行。

异常链路包括空文件、损坏视频、纯音频、零帧、越界时间、未知 profile、错误模型/profile 组合与运行中取消。错误必须非零退出并保留阶段信息，不能生成成功汇总。

### 本地复现

先在独立虚拟环境安装 `requirements-onnx-export.txt`；纯部署只需要 `requirements-onnx-runtime.txt`。
本次所有新增包安装在 `.local/jianying-model-pytorch/tflite/venv`，没有改系统 Python。

```sh
PY=.local/jianying-model-pytorch/tflite/venv/bin/python
$PY -m unittest discover -s research/local-model-pytorch -p '*test*.py'
bunx --no-install vitest run \
  electron/__tests__/jianying-shot-split-torch-engine.test.ts \
  electron/__tests__/jianying-shot-split-compare.test.ts

$PY research/local-model-pytorch/onnx_export.py \
  --model .local/jianying-model-pytorch/vision-batch-phase4-normal-final/normal.pt \
  --input .local/jianying-model-pytorch/vision-batch-phase4-normal-final/case-holdout-video-0-frame-0/inputs.npz \
  --out .local/jianying-model-pytorch/normal-onnx-new-run

$PY research/local-model-pytorch/onnx_infer.py \
  --contract .local/jianying-model-pytorch/onnx-phase4/vision-normal/contract.json \
  --input .local/jianying-model-pytorch/onnx-phase4/vision-normal/provided-fixture/inputs.npz \
  --out .local/jianying-model-pytorch/normal-inference-new.npz
```

所有重跑用新输出目录，不覆盖旧证据。Linux 执行命令和镜像身份以本节记录为准，不能将安装配方当作已跑结果。

本机实际 Linux 完整回放命令如下；从 QCut 工作区运行，使用新的 `results` 目录：

```sh
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --cpus 2 --memory 4g \
  --tmpfs /tmp:rw,size=64m \
  -e PYTHONPATH=/deps:/runner -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD/.local/jianying-model-pytorch/linux-onnx-deps:/deps:ro" \
  -v "$PWD/research/local-model-pytorch:/runner:ro" \
  -v "$PWD/.local/jianying-model-pytorch/onnx-phase4:/models:ro" \
  -v "$PWD/.local/jianying-model-pytorch/linux-new-replay:/results" \
  --entrypoint python3 wzrd-daytona-agent:dev \
  /runner/onnx_replay.py --root /models --out /results --require-no-torch
```

`linux-onnx-deps` 是使用 uv `--target`、`--python-platform aarch64-unknown-linux-gnu --python-version 3.13 --only-binary=:all:` 安装的目标平台 wheels，不是把 macOS 虚拟环境拷进 Linux。
