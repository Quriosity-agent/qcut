# 1080p 竖屏复合美颜：预览与导出验收

分支：`codex/beauty-portrait-preview-export`。基线：`2b973174900cca8cacf066e2cf23b739da79ba2e`。

`main-12s-r4` 已用冻结的 r13 构建完成真实三路导出：每路 12 秒、360 帧、1080×1920、30 fps；三路合计 33 次暂停预览／预编码比较全部满足 RGB 最大差 ≤ 1、alpha 差为 0。第 307 帧的真实 reader → IPC → sidecar → 模型回执身份链也已核对。用户要求的 1080p 视觉里程碑已完成。r14 音频修复后又完成三路暂停回归；额外讲话长测按用户收尾要求于 11:19 UTC 通过 UI 取消，音频固定延迟尚未修复或验收。

## 验收范围

真实视频、1080×1920、30 fps；同时启用 `TotalFace=25`、`EnlargeEye=20` 和 `lip-coral-nude=35`。两个连续片段叠加缩放与裁剪关键帧、四边裁剪、居中的一秒 dissolve。美颜强度是静态值；本轮关键帧指缩放和裁剪，并不表示产品已有美颜数值关键帧。

使用原画面、原生、自研三条实际导出路径，保存完整 MP4。“原生”指 QCut 调用本机剪映原生运行时的结果。预览来自真实 Electron 暂停画面，交替验收选中与未选中片段；编码前 PNG 直接从生产导出 Canvas 取得。PNG 比较不缩放、不配准、不模糊，RGB 最大差不超过 1、alpha 完全相同。最终有损 MP4 的解码、帧数、时间戳、音轨和压缩误差另行记录。

r4 实际采样 `0,30,90,165,180,194,254,270,274,307,359`，包括三次真实失败附近的位置。每路 360 帧完整视频与每路 11 个采样点均已保存；三路合计 33 次暂停预览／预编码比较，不是逐帧 360 次预览像素验收。最大 RGBA 差全部为零时才称“零差”，与 RGB ≤ 1 的容差通过分开报告。

## 本轮修复

- 美颜先处理真实源图像，再应用画面尺寸、裁剪和变换；预览不再先降采样或中心裁剪后推理。
- 导出补齐画布坐标下的裁剪，包括 cover 内容在缩小时不能露出画布外区域。
- 导出开始时快照项目背景色，并传入标准/Muxer 与 optimized 路径；contain 留边及裁剪暴露的区域使用同一背景，准备期间切换项目颜色不会污染当前导出。
- 暂停取帧使用与导出相同的项目帧率、半帧采样和源时间映射。顺序解码边界容差由 1 ms 缩到 100 ns，避免把 23.976 fps 素材的下一帧提前取出。
- 受支持的视频合成暂停预览共用导出 Canvas 渲染器，消除 CSS 与 Canvas 的缩放、边缘抗锯齿差异。未实现的透视、抠图、动画、增强、插帧等不接管。
- 最终导出、精确预览和转场中间画布共用显式 `willReadFrequently: false` 策略。只改最终画布仍有转场残差；三处统一后，记录／重放的 30 帧诊断归零，所检查导出帧保持原值；最终真实引擎结果见下表。
- 共享渲染队列保护跨异步步骤使用的合成画布。过期预览结果不再提交；停滞的媒体下载、源历史解码和 HTML 视频加载可取消，HTML 加载有超时。导出开始时停止新精确预览请求。已经进入原生 IPC 的历史重放事务目前不能即时中断，必须等其完成后丢弃旧结果并释放渲染队列；自研 worker 的取消证据不代表原生宿主也已验证即时取消或故障恢复。
- 原生跟踪器的历史会影响像素。精确合成的原生视频采用固定源帧窗口，在同一原生事务内重建并重放真实历史，再渲染目标；不会依赖“先导出再命中缓存”。普通播放和旧局部预览保留原策略。该模式增加离线渲染耗时，不能视为实时预览。
- 自研检测会产生衣服／边缘假脸。模型拒绝或明确越界的候选以具名错误剔除，真实主脸坐标保持原值；不裁点、不放松 NaN／类型／模型错误。全无效或没有可用身份确认的多个候选仍会报错。12 秒素材第 254 帧另暴露了一个已被 seed 分类拒绝、仍进入 reset 的假候选；现在在 warm 完成后提前执行同一拒绝判断，保留仿射矩阵 32768 上限和真实主脸坐标。
- 首阶段脸型／五官回执确认了原图目标后，后续口红阶段用不可变的同帧身份参考关联当前候选，防止形变后挥手区域被当作新脸。当前关键点仍重新预测；参考只筛选身份。输入尺寸与 RGBA 哈希必须匹配，零匹配、多匹配或超出保守位移边界继续失败。其他阶段和顺序明确记录未应用该约束。
- 第 307 帧的假脸在首阶段就被接受，不能借助后续口红的同帧参考处理。新增 `single-face-bidirectional-v1`：只在当前图有多个有效候选时，检查目标源 PTS 前后各两张真实源帧；四张邻帧各自必须恰好一个有效候选，并且分别唯一关联到同一个当前候选。缺帧、邻帧零脸／多脸、无匹配、多匹配或前后不一致继续失败。单候选保持原预测，不推理邻帧；渲染使用当前候选的关键点，不使用邻帧坐标。
- 四邻证据只接在取得真实解码 PTS、没有稳定化变换的视频合成路径。源读取限定前后 0.5 秒、最多解码 256 帧、10 秒超时及 64 MiB 邻帧像素预算；不会为塞入预算而缩小 4K 证据。Electron 绑定目标与四邻 RGBA、尺寸、有序 PTS 和策略哈希；独立帧缓存包含证据清单哈希。Python 校验固定文件名、大小、alpha、像素哈希和请求身份，返回回执及后续同帧参考必须匹配本次清单哈希。不可用证据不阻止正常单候选处理，也不能把歧义目标转成成功。

精确暂停合成层和旧 `ColorPreviewCanvas` 是不同路径。精确层成功覆盖画面，只证明该次暂停合成；旧底层在 307 附近仍可能因没有双向源证据而报 `found 2`。本轮没有据此宣布旧局部预览、连续播放或实时美颜通过。四邻读取也会增加单候选请求的解码开销，需用实际整段耗时衡量。

`smoke-r5` 使用真实三路引擎完成 1 秒、30 帧导出；三路各 5 个采样点的预览／导出 RGB 和 alpha 最大差均为 0。它证明了该短用例，不能代替 12 秒复合运动验收。

第 307 帧实际应用身份链已由 `main-12s-r4/actual-reader-audit.json` 核对，23/23 项为真：真实导出首次请求未命中帧缓存，模型在当前图发现 2 个有效候选，四邻各自严格单脸且全部唯一关联同一当前候选；实际 reader 的目标与四邻 PTS／RGBA、任务 sidecar、模型确认回执及返回像素哈希相互一致。随后暂停预览合法命中了相同输入与证据清单的帧缓存；它不是第二次独立推理，也不说明首次请求为冷进程。

实际目标源 PTS 为 `10.218541666666667`，输出帧 307 的时间为 `10.233333333333333`。实际清单 SHA 为 `e4372b8f757383da19f9ad278c215bed08faaefe5b8a6bff178dd1f4eaef1809`，后端输出 RGBA SHA 为 `f871b5e778101e32451e443474aec70c27e574f69f90f1791411129a9907f55c`。后者与三次完整诊断渲染一致。诊断清单的 PTS 曾保留六位小数，因此其文件哈希不同；实际请求、实际 sidecar 与实际回执的哈希则完全匹配。该帧截图和实际合成 Blob 相对预编码 PNG 的最大 RGB 差为 1、alpha 差为 0，不写成零差。实时邻帧原始 buffer 未全部留存，但 IPC 哈希已绑定实际 sidecar／回执，并与独立重算的诊断 PNG 像素一致。

固定脸部上下文 ROI 为原始输出坐标 `[80,140,1040,1080]`，960×940 像素；三路所有 11 个采样点使用同一矩形，测量不缩放、不配准。原生与自研 ROI 的最大平均绝对 RGB 差出现在转场第 180 帧：均值 `0.077046764`、P99 为 `1`、最大值 `17`（通道范围 0–255）。这说明二者仍有算法差异，不能宣称像素等价。ROI 是固定上下文区域，不是人脸检测或跟踪，也不替代全画面比较；原图／原生／自研／差分见私有 `main-12s-r4/face-roi-summary/index.html`。

内存记录包含 1957 个样本，采样间隔中位数约 2.038 秒，应用及被记录子进程 RSS 合计峰值为 `3834.984375 MiB`。结束后独立查询本轮记录的全部 858 个 PID，均已不存在；这不是只检查当前子树为空。RSS 合计可能重复计算共享页，间隔间峰值及未记录进程也不在证据内，因此不作长期无泄漏或内存预算通过判断。整段低分辨率残差与时序测量保留为诊断，没有无抖动门槛或运动补偿验收。

音频对齐诊断已修正时间原点：使用源容器呈现时间零点，PCM 索引为比较时间减去首个解码音频 PTS；不再减去首个视频 PTS。Jane 源音频从 0 开始、视频从 0.033 秒开始，旧计算会制造 33 ms 偏差。9 项 CPU 音频回归通过，覆盖无真实偏移、正负延迟、静音／歧义、漂移及缺失音频 PTS；这验证分析器，不代替实际讲话输出或感知口型同步验收。复现与红／绿测试见私有 `audio-time-origin-audit/`。

实际讲话测试进一步发现 Chromium `decodeAudioData` 将 12 秒 AAC 源音频解成 `11.5090625` 秒，产生累计时间收缩。r14 改用按源 PTS 放置样本的解码器，实际恢复为 `12.000` 秒；解码失败仍明确报错。生产完整音频处理图的五个窗口相对源音频保持约 12 ms 固定延迟，相关性为 `0.982667–0.991930`，没有观察到累计漂移。

r14 实际原画面 MP4 的五个窗口仍有 `55.979–56.000 ms` 固定延迟，首尾变化为 0；这不是音频同步通过。`actual-aac-priming-audit.json` 将 MP4 解码音频与实际编码前处理图比较，五窗口均多出 2112 个采样点，即 48 kHz 下 44 ms 的 AAC 编码／封装起始延迟；容器没有声明跳过该延迟的 edit list。约 12 ms 处理图延迟加 44 ms 编码延迟与实际总延迟一致，但这两项尚未修复或接受。输出视频时长为 12 秒，AAC 音轨／容器约 12.074667 秒；不能用视频帧数代替音频时长验收。三路讲话 PCM 一致性和感知口型同步未完成。

## 明确保留的边界

- 独立复合仍只渲染一个已确认目标。真实多人和零脸素材已复现失败；四邻严格单脸只解决特定候选歧义，不实现多人渲染。仅在目标瞬间出现真实第二人的情况明确未验证，不能宣称多人、完全遮挡或出画后恢复通过。
- 精确暂停层的通过不等于旧 `ColorPreviewCanvas` 或连续播放通过；原生固定历史和自研四邻确认的吞吐也不等于实时能力。
- 四邻不足、超时、超过 64 MiB、反向／HTML 取帧回退、稳定化等条件不能用该证据消歧。混合普通几何与局部包时，形变后的局部子阶段也不套用原始源历史，可能继续明确失败。
- 比较原生与自研结果不等于二者已经达到像素等价；差分需单独阅读。
- 原生固定历史窗口与原来的连续跟踪历史不同，时序变化和性能需要分别度量。
- 音频约 56 ms 固定延迟仍未修复／验收；三路讲话 PCM 一致性与感知口型同步未完成。整段帧差、短期 RSS 斜率和相关性不能分别替代无抖动、长期无泄漏或口型同步验收。
- 本轮端到端导出使用 Muxer 路径；没有据此宣称所有导出后端、所有特效和所有人脸条件均通过。
