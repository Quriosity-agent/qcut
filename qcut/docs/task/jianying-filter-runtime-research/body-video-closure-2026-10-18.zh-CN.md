## 2. 方法

### 2.1 三方对照（第 1–3 步）

`apps/web/src/test/e2e/body-video-close-threeway.e2e.ts`：同一条片段依次以 untouched / native / independent 三种设置走**真实导出**（muxer 引擎，与产品相同），每路：

- 180 帧 MP4；
- 16 个采样帧（0,12,…,179）的**编码前导出画布 PNG**；
- 同一批采样帧**暂停后已提交的 canvas-composition 预览 PNG**（真实预览画布，不是缓存键比较）。

untouched 这一路没有 composition plan，预览走普通 video 路径，没有 composition 画布可读；它只保留导出帧作为原图参照。≤1 色阶的预览↔导出判定针对原生与自研两路。

`scripts/body-video-close-report.py` 解码三路 MP4 做全 180 帧统计（效果量、原生↔自研误差、残差跳变、身体区域是否被改变），编码前 PNG 样本做 ≤1 判定与原生↔自研无编码器对照，并生成对照页。

### 2.2 操作不变性（第 4 步）

`apps/web/src/test/e2e/portrait-independent-body-video-close.e2e.ts`：以顺序导出为基准，依次验证倒序跳播（缓存不变）、清缓存重算、导出进行中取消、**计算进行中 worker 被杀**、进程重启（带缓存 / 清缓存）后 180 帧 framemd5 全部一致。

## 3. 代码发现与修复

### 3.1 计算进行中 worker 丢失会让导出失败（已修，E2E 已证明，见 §4.4）

阅读 `beauty-lab-independent-worker.ts`：常驻 worker 退出时，**正在处理的请求被以通用错误拒绝**，下一次请求才会懒启动新 worker；`beauty-lab-independent-body-video.ts` 只把 `IndependentSequenceGapError` 转成 `replay`，其它错误直接抛出 → 导出中断。原有 E2E 的杀进程发生在导出完成之后，所以没覆盖到。

修复：worker 模块新增 `IndependentWorkerExitedError`（区分「自己死掉」与「有原因的 stop」）；会话渲染器在收到该错误时**重提交一次**——新 worker 没有会话历史，会按既有协议回复 gap → `replay`，渲染端已经会从检查点重放。连续两次死亡原样抛出。单测：`beauty-lab-independent-worker.test.ts`、`beauty-lab-independent-body-video.test.ts`。

### 3.2 harness 的坑

- 原图路径没有 composition 画布（见 2.1），采集预览会等满 300 s 超时 → 改为按路径决定是否采集预览。
- 原生 inspect 结果没有顶层 `ready`，就绪判定是 `state === "ready" && available`。
- 导出状态在 `__exportStore.getState().progress.isExporting`，不在顶层；不变性 E2E 第一次跑在"取消导出"一步等了 900 s 的 `undefined`。
- 产品取帧规则：时间线第 k 帧在 `(k + 0.5) / fps` 处采样，取覆盖该时刻的源帧（epsilon 偏向新帧）。离线复现若按帧起点取帧，30 fps 时间线上 23.976 fps 源会有 71/180 帧取错，表现为"解码噪声" 5–10 色阶。

研究资料里原生序列对拍通过的那次本来就是 `--mode 1`（`本机连续对照结果/report.json`），mode 2 是照片的冷态规则；接进会话时选了 mode 2 并把"锁住后的相等"记成了通过。

第 0 帧：`BodySkeletonSequence` 的 coarse 通道只播种、不输出外部骨架，自研第 0 帧原样输出；产品里的原生路径第 0 帧就有完整效果。离线验证：播种帧紧接着在同一帧跑 refine 即可输出骨架；第一帧的几何再做 8 次更新（与照片路径 `STILL_UPDATES` 一致）后，第 0 帧 vs 原生编码前 PNG 从 11.78 降到 3.43 色阶（其中约 2.0 是 Chromium/FFmpeg 解码差），第 1–11 帧均值 6.48 → 4.24。第二次 refine 不改变结果。

修复（`body_smart_sequence.py`，manifest 重钉 `93a9a99d…`）：`PersistentCombinedBody(mode=1)`；coarse 播种后同帧 refine（收据 `seedRefined`）；会话首个身体帧更新 `FIRST_BODY_UPDATES = STILL_UPDATES = 8` 次（收据 `compositionUpdates`）。单测与真实模型场景测试同步更新：第二人入画时不再断言网格与单人跑相同——锚点逐帧刷新后，refine 裁剪框和全图人脸跟踪都会看到第二个人，这是多人身份关联的范围，不在单人验收内。

### 3.4 原生第 0 帧不依赖预热（假设被否定）

原生 provider 的跟踪域按 `(宽, 高, sourceKey)` 复用，时间相同不算中断（`isPortraitTrackingDiscontinuity`），所以曾怀疑第一轮原生第 0 帧的稳态来自暂停预览的预热。用 `QCUT_BODY_CLOSE_PARK_SECONDS=3` 把播放头停到 3 s 再导出（第 0 帧对跟踪器是倒退 3 s 的中断，重开宿主进程）得到的冷启动原生，与热原生在 9 个编码前采样帧上逐字节相同，前 40 帧几何轨迹也相同（§4.3）：原生库第一帧就输出收敛后的几何，没有多帧爬升。自研"首个身体帧更新 8 次"因此是在复刻原生的首帧行为，而不是迁就预热。

### 3.5 原生自身的瞬态

原生导出在第 119 帧拉腿量减半一帧（changed 0.308 → 0.169 → 0.304），第 144–150 帧拉腿几乎消失（底部位移 73 → 8.7 → 19 → 54 px）；自研两处都平滑。这些是原生跟踪的抖动，不复刻。

### 3.6 重启后会话身份改变（已修，复跑见 4.5）

重启后的"带缓存"导出与重算一样慢，用户数据目录里出现**两个**会话目录（各 15 份检查点）：会话身份 = sha256(引擎, 片段身份, 尺寸)，而片段身份（`independentBodyVideoClipIdentity`）在工程重开后改变，帧缓存与检查点全部失效，只能从第 0 帧重算。结果仍逐位一致（不变性成立），但重启后失去了缓存的意义。两个根因：

1. 片段身份把 `mediaItem.file` 的 `name/size/lastModified` 算了进去。首次导入时 `File` 来自文件选择器（原文件名、磁盘 mtime）；工程重开后存储层用 OPFS 的 `fileHandle.getFile()` 重建 `File`——按 OPFS 条目名（= 媒体 id）命名、`lastModified` 为写入时间，字节数不变。落盘记录 `MediaFileData.lastModified` 同样不稳定（重载后任何 `saveMediaItem` 都把它改写成 OPFS 时间），仓库里也没有现成的内容哈希。修法：身份的媒体部分只用媒体 id 与字节数（`MediaFileData.size`，OPFS 原样保留；保留字节数是因为时间线 relink 会同 id 换文件），`schemaVersion` 升到 2。
2. 只修 1 之后复跑，重启后仍是两个会话目录、带缓存导出 224 s：工程重开时 `normalizeLoadedTracks` → `normalizeMediaPortraitAdjustments` 把 `portraitAdjustments` 重写成规范形（只留非零值、固定键序、默认字段丢弃），而面板在会话内写入的是原始对象，两者 `JSON.stringify` 不同。修法：身份用加载器同一个 `normalizeMediaPortraitAdjustments` 规范化编辑后再哈希。

单测 `independent-body-video.test.ts` 新增"File 重建后身份不变"与"加载器规范化后身份不变"（用真实 `normalizeMediaElement` round-trip）两例，修前都失败。close E2E 的重启阶段新增 `restart_session_reused`（会话目录只有一个），并把 Electron 意外退出的 code/signal/时间记进 evidence。

## 5. 结论

单人动态美体在产品里闭环：同一 180 帧真实走动片段，自研与原生都在每一帧改变身体区域；暂停预览画布与编码前导出帧两路都是 0 色阶；原生↔自研每帧均值 3.69 色阶（第一轮 9.99），>5 色阶的帧全部是原生自己的拉腿瞬态；六项操作不变性全部 180/180 一致，另一个工程、另一次进程的顺序导出与本对照的自研导出 180/180 逐字节相同；修复片段身份后重启的带缓存导出从 224 s 降到 23.6 s，会话目录只剩一个（4.5）。

残差（不阻塞单人验收）：稳态带顶比原生低 5–60 px（半身段更大）、瘦身幅度低 0.2–0.4 px，对应照片阶段记录的"原生 pivot ≈ 直接值的 97.7 %"未知机制；原生在第 119、135、144–150 帧的拉腿塌陷不复刻。
