# 1080p 美体编辑器操作闭环

日期：2026-10-20。基线：`7bd5ceacc996b924c25563f430651dd1046d6ce0`。
分支：`codex/body-editor-native-1020`。

本轮验证编辑参数、暂停跳播、取消和工作进程崩溃之后，是否仍能得到同一套画面。
“预览与导出一致”与“自研等于产品默认原生”是两个独立结论。
操作与故障注入矩阵针对自研常驻进程；产品原生参加相同素材的预览、导出与差分对照。
本轮没有对原生宿主执行同一套取消和崩溃注入矩阵。

## 代码改动

美体历史会话原来只包含时间线存储的 `portraitAdjustments`。Media Lab
可以合成额外的眼部处理参数，而不改变这个存储字段。这会让不同的实际输入
复用同一个身体跟踪历史。

现在会话身份同时包含规范化后的实际渲染参数，并在首次异步操作前复制参数。
中途修改参数不会改变已经开始的历史重放；恢复原参数仍能找到原会话。
取消发生在媒体身份计算之前或期间时，不再启动解码器或提交新帧。

本轮没有更改 Python 美体算法、模型权重、原生宿主更新次数或跟踪初始化规则。
不会通过添加几何迭代、重复输入目标帧或临时更换原生后端来降低差分。

## 验证口径

- 单人、1080 × 1920，30 fps 时间线；源素材为 24000/1001 fps。
- 智能美体：瘦身 40、长腿 30；参数操作另测瘦身 `40 → 55 → 40`。
- 每次完整导出记录全部编码前 RGBA SHA-256，并完整解码 MP4 计算逐帧摘要。
- 暂停预览读取已经提交的全分辨率合成图，避免把 CSS 缩放或视频编码损失算作渲染误差。
- 冷跳播清除画面缓存，且要求工作进程实际完成新的请求。
- 取消记录实际取消 IPC 进入时的对应帧、请求和 worker pending 状态。
- 崩溃测试在主进程同一次调用中选择尚未返回的帧请求并对其 worker 发出 SIGKILL。
- 重启分别检查缓存命中和删除画面缓存后的重新计算；会话目录复用不等于 checkpoint 已恢复。

操作测试 `operations-180-r3/e2e-evidence.json` 最终状态为 `passed`，
10 项检查全部通过。完成 7 次 180 帧导出，另一次取消导出停止于已捕获 30 帧。

| 操作 | 实测结果 |
| --- | --- |
| 正常导出与暂停预览 | 180 帧导出完整，5 个暂停预览采样 RGBA 相同 |
| 瘦身 40 → 55 | 179 帧改变，首帧保留原生 CPU 配置的初始化行为；5 个改参预览与对应导出相同 |
| 恢复到 40，清缓存跳到 179、0、90、1、178 帧 | 5 次均实际调用 worker，画面与原基线相同 |
| 清缓存整段重新导出 | 180/180 编码前与解码画面相同 |
| 处理中取消 | 取消 IPC 到达时第 30 帧仍 pending；取消返回 true；后续完整导出 180/180 相同 |
| 处理中 SIGKILL | 第 30 帧请求未完成时终止原 worker；新 worker 从第 24 帧 checkpoint 恢复并重放，完整导出 180/180 相同 |
| 应用重启，使用缓存导出 | 180/180 编码前与解码画面相同 |
| 应用重启后删除画面缓存重算 | 180/180 编码前与解码画面相同，会话身份保持稳定 |

17 次操作预览比较全部通过，未捕获页面异常为 0。控制台原始记录仍保留
HTTP 401 资源响应和主动取消产生的 AbortError；不据此宣称云登录或网络功能已验收。
第一次长运行因测试定位器问题中止，第二次在调参时未打开外层属性页而失败；
修复后先用保存工程验证真实滑块操作，再完成上述最终运行。早期失败记录保留。

最终又从磁盘重新解码全部 7 份完整导出，与记录的逐帧摘要及正常基线复核，
结果通过。另一个工程、另一次运行中的三方对照自研导出，与操作矩阵正常导出
180/180 帧完全相同，最大差为 0。

已完成的 180 帧编辑器三方对照：原图、产品原生、自研均输出 6 秒完整视频；
原生、自研分别抽取 8 个暂停预览与编码前导出帧，两条路径的最大 RGB
和 Alpha 差均为 0。产品原生与自研的全部 180 帧解码画面平均 RGB 差
为 6.205301 色阶，不能称为产品原生对齐。

另外比较修复前 60 帧基线与修复后导出的第 0、20、39、59 帧，
4 个编码前 RGBA 摘要完全一致。此项只证明这 4 个固定参数样本没有像素回归。

## 原生配置边界

独立的原包探针使用相同 60 帧原图，在第 20、40 帧切换参数：
当前自研与 **Bef 效果图 / modern skeleton CPU / warm-reset** 参考
60/60 帧 RGBA 完全一致。产品默认 **Swing / CoreML / cold-start**
仍有差异，平均 RGB 差 3.669544，最大单通道差 192。

该探针保持一条连续历史；编辑器产品路径另有 source-window 预滚规则。
因此探针的 3.669544 与编辑器三方对照的 6.205301 不能当作改进前后指标。
调用时序、初始化和历史不同，必须分别保留配置。

原生配置、动态调用证据及复现方法见
[BODY_VIDEO_PROFILES.md](../../../research/jianying-runtime-probe/BODY_VIDEO_PROFILES.md)。

## 复现

先构建桌面应用，并配置本地 `QCUT_INDEPENDENT_BEAUTY_RUNTIME`、
`QCUT_INDEPENDENT_BEAUTY_PYTHON` 与 `QCUT_BODY_CLOSE_SOURCE`。
源素材 SHA-256：
`d1f6593f61723b2a838c8bc962533d192f3071b92f0035a71fa601ca63b471f4`。

两项 Playwright 测试分别为：

```text
apps/web/src/test/e2e/body-video-close-threeway.e2e.ts
apps/web/src/test/e2e/portrait-independent-body-video-close.e2e.ts
```

设置 `QCUT_E2E_OFFSCREEN=1`、`QCUT_BODY_CLOSE_SECONDS=6`，
为每次运行指定新的输出目录；操作测试使用
`QCUT_BODY_CLOSE_INVARIANCE_OUTPUT`，三方对照使用 `QCUT_BODY_CLOSE_OUTPUT`。
并行运行必须使用不同的 `QCUT_API_PORT` 和 `XDG_STATE_HOME`。
并行运行耗时只用于诊断，不作为性能基准。

使用 `scripts/body-video-close-report.py` 生成视频、差分和统计；
`--verify-operation-videos` 会重新解码实际导出，补充核验操作记录。

构建、E2E 类型检查、改动文件 Biome 检查通过；56 项相关前端测试、
57 项进程与队列测试、11 项报告测试通过。两组真实 Electron E2E
分别完成三方对照与操作闭环。
