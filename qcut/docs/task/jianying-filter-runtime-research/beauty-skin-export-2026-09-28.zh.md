# 皮肤三项同尺寸导出校准

日期：2026-09-28。分支：`beauty-kpop-v2`。承接 [八项 UI 与截图差分](beauty-skin-ui-2026-09-28.zh.md)。

后续进展：[祛斑祛痘处理分辨率修复](beauty-blemish-resolution-2026-09-28.zh.md)已使50/100档真实导出差分MAE下降19.4%/33.1%；眼周色边仍未解决。本文保留修复前基线，不回写历史数值。

## 结论

已完成磨皮、祛斑祛痘、清晰各50/100，以及前后两次零值的双端真实导出。不是独立原生探针代替 QCut 编辑器，也不是播放器截图代替剪映导出。

发现并修复了一项导出基线问题：启用美颜但参数归零时，QCut 原来改走 Native CLI；非零时则由 export factory 强制走 Canvas/WebCodecs。两条链路的缩放、编码和色彩标记不同，会混入整幅图的差异。现在美颜总开关开启时，即使所有值为0，也保持 Canvas/WebCodecs；关闭总开关或没有美颜配置的素材仍保留原路由。复合片段中的零值美颜同样覆盖。

这不是美颜强度修复。六个非零档位的导出首帧 PNG SHA-256 在修复前后全部相同，变的是零值基线。没有修改模型、SDK、参数增益、stage 顺序或私有资源。

效果还不能宣布完全对齐：清晰100的变化幅度接近，磨皮仍有纹理差异，祛斑祛痘的局部范围和眼角异常仍未解决。

## 导出链路问题

修复前的 QCut 零值视频为 `yuvj420p / pc`，矩阵/原色/传递标记缺失，约0.44 Mbps；六个非零视频则已是 `yuv420p / tv / bt709`，约2.26至3.09 Mbps。剪映约8.04至9.94 Mbps。缺少标记本身不能直接证明像素转换错误，但零值与非零走不同链路已由代码路由和实际文件共同确认。

生产改动集中于 `apps/web/src/lib/export/jianying-local-color-export.ts`：导出选择以 `portraitAdjustments.enabled` 为条件，不再以“是否有非零有效参数”为条件。像素渲染仍自行跳过零强度处理，不强行调用美颜算法。

取舍：已启用但归零的美颜片段不再享受 Native CLI 快速路径；显式关闭美颜仍恢复原路径。本修复不统一所有导出引擎，也不保证总开关开/关跨引擎比较完全相同。

## 复现

```bash
cd apps/web && bun run build:electron && cd ../..
QCUT_REAL_PORTRAIT_IMAGE_PATH=/path/to/portrait.jpg \
QCUT_PORTRAIT_SKIN_EXPORT_OUTPUT=/path/to/qcut-output \
  bunx playwright test portrait-skin-export-reference --workers=1 --reporter=line
python3 scripts/compare-portrait-skin-exports.py \
  /path/to/qcut-output/report.json /path/to/jianying/manifest.json /path/to/comparison
python3 -m unittest discover -s scripts/__tests__ -p 'test_portrait_*.py'
```

剪映manifest须有同源 `sourceSha256`，`samples`中的 `name/values/exportPath` 与QCut报告对应，共6个独立非零案例及 `neutral`、`neutral-after`。导出前手动核对原图与参数，不能只填写manifest宣称采集成功。
