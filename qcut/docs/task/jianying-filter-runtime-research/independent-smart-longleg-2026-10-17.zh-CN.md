# 自研智能美体：长腿（2026-10-17）

> 2026-10-18 起由 [十项智能美体](independent-smart-body-2026-10-18.zh-CN.md) 取代：长腿改用研究的真实状态链，其余九项也已接入。下文保留当时的记录。

分支 `beauty-body-1017`。把桌面研究「美体原生与自研核查_20261017」里已验证的长腿链接进自研引擎。现在编辑器的「智能美体 · 长腿」在自研引擎下可以用：美颜实验室、时间线预览和导出都走同一条链。其余九个智能美体参数仍未接入，自研遇到它们会报「不支持」，不会悄悄改用原生。

模型权重不进 Git。它只放在本机私有运行时 `research/independent-beauty/runtime/research/body-skeleton-v1.npz`，和其他私有模型放在一起。这个目录在 QCutBeauty 卷上，已被 `.gitignore` 排除，打包时也不会带上。

## 链路

1. **算法图。** 先把画面等比缩放到长边 640。整数倍缩小走 2×2 面积均值，其余走原生的线性缩放。
2. **粗检测。** 长边 224、各边补到 16 的倍数，转 BGR 减 128，跑多人定点网络（18 个关节热图加背景、19 组肢体方向场），按原生解码规则分组。第一个人只作为跟踪种子，不直接输出。
3. **两次精修。** 每次在当前姿态外取一个框，等比放进 144×192，跑单人定点网络（17 个 COCO 关节），转成 18 点并和上一次姿态平滑。第二次的结果就是效果用的姿态。
4. **长腿状态。** 姿态按算法图归一化（y 朝上），算肩、髋、膝中心和身体尺度，得出长腿的终点和支点高度。强度：滑杆 u 对应目标 0.35 × u / 100，复位后的第一帧直接到目标。
5. **网格。** 30×30 网格，只动纵向：支点以下整体往下拉，支点到终点之间渐变，边界只能往里收。最后用 Metal 线性采样、边缘夹取画出来。

两张定点网络在 NumPy 里逐位复现（原来的研究代码用 Torch 卷积；改为 float64 卷积，整数层的部分和远小于 2^53，结果不变）。引擎的 Python 是 3.12，没有 `math.fma`，改用单次舍入的精确实现；三次插值改成 NumPy 向量化，逐位等于原来的逐点写法。

## 实测：原生成片走的是哪条路

用 `bytenn_model_capture.mm` 新增的引擎输入输出记录（`QCUT_BYTENN_CAPTURE_ENGINE_IO=1`），在一张 720×1280 全身照和另外八种尺寸上抓了原生美体渲染时三次网络推理的真实输入和输出。证据只在本机：`.local/jianying-model-pytorch/body-skeleton-io-20261017/`。

- **桌面研究的单图链和原生成片不是同一条路。**
  - 研究直接把原图送进检测器。原生成片则先缩到长边 640 的算法图，网络输入因此差到 54 个色阶。
  - 研究用粗检测的点直接出图，原生成片用的是两次精修后的点。
- **按原生成片的路线：**
  - 粗检测输入逐字节一致。
  - 两次精修的裁剪框和原生一模一样：(70, 138, 220, 443)，然后 (72, 139, 214, 430)。
  - 第一次精修的输入逐字节一致。
- **第二次精修原生改用了 CoreML 浮点网络，CPU 定点链做不到逐位一致。**
  - 它的裁剪像素和我们的完全相同，归一化是每个通道除以 255、减 0.5、再除以 0.25。
  - 18 个关节里有 11 个差 1–5 个算法图像素。
  - 原生在 CoreML 准备好之前走 CPU，所以原生自己的结果也随加载状态变化。自研固定走 CPU，结果确定、可复现。
- **算法图的缩放规则：** 720×1280、1080×1920、1440×2560、540×960、1280×720、1920×1080、1000×1000、480×640 都逐字节一致；999×1333 这类非整数倍且超过 2 倍的缩小还对不上，记为未验证。
- **旧的骨骼权重是坏的。** 9 月收集的 `811519c5c6501093`、`c3388ac4a17502f3` 两张子网权重切错了，算出来的结果和输入无关，当时的「逐位一致」只是同一份坏权重自己比自己。正确权重的哈希是 `fd860348…`、`a4fbff21…`，和桌面研究从模型文件里直接读出的一致。

## 和原生的差距

研究里的描述子在第一帧把基准高度从 0 开始平滑，只到实测值的 40%，腿部区域因此比原生低很多。原生静帧的支点约在实测值的 97.7% 处。我们按原生成片拟合：静帧把同一个姿态更新 8 次（基准到 98.3%）。这是拟合，不是还原出的机制。

在原生成片的同一姿态上比较（平均色阶差，越小越接近；括号里是原生自身的改变量）：

| 画面 | 研究的单次更新 | 直接取实测 | 更新 8 次 |
|---|---|---|---|
| 540×960 | 8.53（9.15） | 3.62 | 1.98 |
| 1080×1920 | 8.77（9.36） | 3.92 | 1.88 |
| 1000×1000 | 4.82（5.16） | 1.92 | 0.88 |
| 1440×2560 | 9.02（9.63） | 2.51 | 2.99 |

完整的自研链（第二次精修也走 CPU）与原生成片的平均差：

| 画面 | 原生改变量 | 自研与原生之差 |
|---|---|---|
| 480×640 | 6.55 | 0.86 |
| 1000×1000 | 5.16 | 1.06 |
| 540×960 | 9.15 | 1.64 |
| 1080×1920 | 9.36 | 2.28 |
| 999×1333 | 6.99 | 2.31 |
| 720×1280（QCut 原生提供方） | 9.26 | 2.45 |
| 1440×2560 | 9.63 | 4.65 |
| 横屏、人物很小（1280×720、1920×1080） | 0 | 0（双方都没检测到人） |

单帧约 0.3–0.5 秒（Metal 宿主首次编译另需约 1 秒）。

## 实现

**引擎**（`research/independent-beauty/research/`，全部登记在 `source-manifest.json` 的 `generatedFiles`，共 289 个固定文件）：

| 文件 | 作用 |
|---|---|
| `body_espresso_graph.py`、`body_espresso_fixed.py` | 定点图解析和 NumPy 解释器 |
| `body_skeleton_model.py` | 读私有资源、校验两张网络的哈希 |
| `body_skeleton_preprocess.py` | 原生线性缩放与粗检测输入 |
| `body_skeleton_kernels.py`、`body_skeleton_decode.py` | 热图、方向场、分组、映射、精修和静帧姿态 |
| `body_longleg_state.py`、`body_longleg_mesh.py` | 描述子、长腿状态和网格 |
| `body_mesh_metal.swift`、`body_longleg_render.py` | Metal 网格宿主和渲染入口 |

- 目录新增控制项 `StretchLeg`（分组 `body`）和 `smart-body` 阶段。该阶段标了 `afterMakeup`，规划器把它排在美妆之后，和原生「美体最后」的顺序一致。
- `body_adjust_*` 只对应 `body` 分组的控制项，`face_adjust_*` 只对应其他分组。
- 常驻执行契约是 `{'controls': 'json'}`，并支持原尺寸渲染。

**私有权重：** `research/local-model-pytorch/build_body_skeleton_assets.py` 从本机已安装的模型文件解出两张网络，校验哈希后写入引擎运行时。它只读文件，不加载厂商库。输出可重复，每次生成的字节相同。运行时清单 `electron/beauty-lab-runtime-payload.json` 增加了这个文件（共 363 个），`inspect` 会校验它。

**Electron：**
- 目录 schema 允许控制项带 `group`。
- `inspect()` 对 `body` 分组报告 `body_adjust_StretchLeg`。
- 请求映射时，前缀只能对上自己分组的控制项。

界面和导出不用改：时间线适配器按引擎报告的控制项放行，美体参数本来就让导出走渲染器。
