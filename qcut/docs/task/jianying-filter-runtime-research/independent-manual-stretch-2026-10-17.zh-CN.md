# 自研手动美体：拉长（2026-10-17）

分支 `beauty-body-1017`。接 [美体审计](body-beauty-audit-2026-10-15.zh-CN.md) 的建议 #3：自研先做手动拉长，它不需要骨骼模型。现在自研引擎可以渲染编辑器的「手动美体 · 拉长」，在美颜实验室、时间线预览和导出里都能用。瘦身和放大缩小还没做，自研遇到它们会明确报「不支持」，不会悄悄改用原生。

## 原生拉长的规则（实测）

测法：把坐标编码成图像输入原生拉长。R 通道是粗坐标，G/B 是周期 32 px 的正弦和余弦相位。从输出就能逐像素读回「这个像素取的是源图哪一行」。

覆盖范围：
- 7 种尺寸：720×1280、1280×720、1080×1920、1920×1080、1000×1000、999×1333、1131×1130；
- 5 组上下线，外加 3 个极窄区域；
- 强度 ±10 到 ±100。

证据只在本机，不进 Git：`.local/jianying-parity/body-manual-native-20261017/`。里面有探针脚本、渲染图和 `cases.json`。

- **只动行，不动列。** 区域内是线性缩放，区域上下两段整体平移。
- **每侧移动量**（全强度时，按强度线性缩放）：
  - 拉长：每侧向外移 5 % 画面高度；
  - 收缩：每侧向内移 2 % 画面高度，最多为区域高度的一半。

  像素数按原生的单精度算法截断：`int(f32(f32(比例) × (f32(上) − f32(下))) × f32(H))`。28 个实测值全部吻合；改用双精度会错 3 个，例如窄区域时 64 会算成 63。
- **网格缩放。** 算出源行后，原生网格还会以画面中心为基准把采样位置放大 250/249。
- **收缩时边缘的条带。** 收缩后，画面上下会各露出一条没有被覆盖的条带，条带里显示原图。是否被覆盖按缩放之前的网格坐标判断；采样时夹到边缘行。中心正好落在边界线上的行，顶部算被覆盖、底部不算。例如 -50 时顶部 12 行、底部 13 行，和原生逐行一致。
- **强度为 0 时原样输出。** 编辑器里的强度范围是 ±50，原生收到的是 ±0.5。

**没有复刻的部分：** 原生在横向还有一个亚像素重采样。它约为 1/625 的居中缩放，再加上一个随宽度变化的 0 到 −0.5 px 偏移（宽度不是 5 的倍数时为 −0.5 + 0.1·(W mod 5)），画面最外 1 px 钉住不动。它对 5 的倍数宽度没有统一规律，所以没有复刻，自研的列保持不动。

## 一致性

- **合成坐标图（行映射）：**
  - 拉长时平均误差 ≤0.03 px，最大 ≤0.6 px。
  - 收缩时平均误差 ≤0.03 px，最大 ≤2 px。最大值出现在条带旁约 10 行的边缘过渡区。
  - 极窄区域收缩到几乎为零时除外。
- **原生审计照片（720×1280，±50）：**
  - 平均差 2.5–2.6 个色阶，p99 为 20；原生相对原图的平均改变量是 15–20。
  - 这个差值几乎都来自上面那个横向亚像素偏移：只要把 −0.5 px 补上，平均差就降到 0.7，p99 降到 4–5。
- **真实提供方与 Python 渲染器：** 两者输出逐像素一致（最大差 0）。常驻执行时每张约 0.6 秒。

## 实现

**自研引擎**（`research/independent-beauty/`，已登记在 `source-manifest.json` 中）：
- `research/manual_body_render.py` 是 QCut 自有的渲染器，用 numpy 按行做双线性采样。回执包含：
  - 隔离证明；
  - 输入和输出的 RGBA 哈希；
  - 每侧移动的像素数。
- `research/independent-pipeline-catalog.json` 新增 `manual-body` 阶段，位置在肤质 GAN 之后、脸部特征之前，和原生「先肤质、再手动美体、再脸型」的顺序一致。
- `src/independent-pipeline-plan.ts` 接受 `manualBody`：
  - 按编辑器的范围校验（强度 ±50，上线 ≥0.02，下线 ≤0.98，上下线间距 ≥0.02）；
  - 只保留非零的工具。没有生效工具时，规范参数里不出现 `manualBody`，所以旧的计划和回执不变。
- `research/independent_pipeline.py`：
  - 计划校验允许 `manualBody`；
  - 该渲染器支持原尺寸渲染。
- `research/independent_stage_runner.py` 登记了常驻执行的参数契约。

**Electron：**
- `beauty-lab-independent-manual-body.ts` 统一定义拉长的 schema 和规范化规则。单张渲染、逐帧渲染和帧缓存键都用它。
- 帧缓存键加入了拉长参数；没有拉长的请求，键和以前一样。
- `inspect()` 报告 `manualBodyTools: ["stretch"]`。
- `beauty-lab-runtime-payload.json` 重新绑定了新的清单哈希。

**界面：**
- 时间线和美颜实验室的适配器会把生效的拉长传给引擎。
- 瘦身和放大缩小显示为「自研不支持：手动美体·瘦身／放大缩小」，预览和导出会报错，不会改用原生。

**顺带修的导出路由问题：**
- API 导出判断「片段的美颜必须走渲染器」时，原来只看数值类参数。只有美妆、手动美体、手动精修或分人物设置的片段，在 auto 下会被送去 native，导出结果没有这些效果。
- 现在用 `electron/types/portrait-export-policy.ts` 判断。主进程运行时不能加载 `packages/`，所以这里是 editor-core `hasMediaPortraitAdjustments` 的镜像；镜像测试逐例比对，保证两者一致。
