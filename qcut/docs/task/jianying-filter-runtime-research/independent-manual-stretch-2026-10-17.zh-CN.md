# 自研手动美体：拉长、瘦身、放大缩小（2026-10-17）

分支 `beauty-body-1017`。接 [美体审计](body-beauty-audit-2026-10-15.zh-CN.md) 的建议 #3：自研先做手动美体，它不需要骨骼模型。现在自研引擎可以渲染编辑器「手动美体」的全部三个工具：拉长、瘦身和放大缩小。美颜实验室、时间线预览和导出里都能用。如果装的是只会拉长的旧引擎，自研遇到瘦身和放大缩小会明确报「不支持」，不会悄悄改用原生。

## 原生拉长的规则（实测）

测法：把坐标编码成图像输入原生拉长。R 通道是粗坐标，G/B 是周期 32 px 的正弦和余弦相位。从输出就能逐像素读回「这个像素取的是源图哪一行」。

覆盖范围：
- 7 种尺寸：720×1280、1280×720、1080×1920、1920×1080、1000×1000、999×1333、1131×1130；
- 5 组上下线，外加 3 个极窄区域；
- 强度 ±10 到 ±100。

证据只在本机，不进 Git：`.local/jianying-parity/body-manual-native-20261017/`。里面有探针脚本、渲染图和 `cases.json`。

- **只动行，不动列。** 区域内是线性缩放，区域上下两段整体平移。
- **每侧移动量**（全强度时，按强度线性缩放）：
  - 拉长：每侧向外移 5 % 画面高度；
  - 收缩：每侧向内移 2 % 画面高度，最多为区域高度的一半。

  像素数按原生的单精度算法截断：`int(f32(f32(比例) × (f32(上) − f32(下))) × f32(H))`。28 个实测值全部吻合；改用双精度会错 3 个，例如窄区域时 64 会算成 63。
- **网格缩放。** 算出源行后，原生网格还会以画面中心为基准把采样位置放大 250/249。
- **收缩时边缘的条带。** 收缩后，画面上下会各露出一条没有被覆盖的条带，条带里显示原图。是否被覆盖按缩放之前的网格坐标判断；采样时夹到边缘行。中心正好落在边界线上的行，顶部算被覆盖、底部不算。例如 -50 时顶部 12 行、底部 13 行，和原生逐行一致。
- **强度为 0 时原样输出。** 编辑器里的强度范围是 ±50，原生收到的是 ±0.5。

**没有复刻的部分：** 原生在横向还有一个亚像素重采样。它约为 1/625 的居中缩放，再加上一个随宽度变化的 0 到 −0.5 px 偏移（宽度不是 5 的倍数时为 −0.5 + 0.1·(W mod 5)），画面最外 1 px 钉住不动。它对 5 的倍数宽度没有统一规律，所以没有复刻，自研的列保持不动。

## 原生瘦身的规则（实测）

测法同上，只是每个用例各渲染一张横坐标图和一张纵坐标图，所以能读回每个像素取的源点（x 和 y）。

覆盖范围：
- 7 种尺寸，同拉长；
- 矩形：x 0.5、y 0.52、宽 0.42、高 0.58，旋转 0° 和 18°；另有 0.2×0.2 的小矩形；
- 强度 ±50 和 ±100（编辑器单位）。

- **坐标。** x、y 是矩形中心，y 自下而上；宽、高分别按画面宽、高计。旋转 θ 时，矩形的横轴在自上而下的像素坐标里是 (cos θ, sin θ)。
- **只沿矩形横轴移动。** 正强度向竖直中线收，负强度向外推。中间高度、左右各四分之一处移动最多；到矩形的左右边和上下边减到零；矩形外不动。
- **形变场的形状固定。** 按矩形自己的坐标 (u, v) 表示时，所有尺寸、横竖屏和旋转角都是同一个形状（相互差 0.7 px 以内），而且与强度严格成正比（差 ≤0.1 px）。全强度时峰值是 0.204 个半宽。没有找到能在 1 px 内复现它的简短公式，所以存成一张 41×41 的表（`manual_body_slim_field.json`，四分之一象限，步长 0.025），按双线性插值使用。
- **反解。** 原生的场描述的是源点移到哪里。渲染时对每个输出像素用 12 步不动点迭代反解出源点；场的斜率远小于 1，迭代收敛。

## 原生放大缩小的规则（实测）

覆盖范围：圆心 (0.5, 0.5) 半径 0.24，以及 (0.3, 0.7) 半径 0.12；7 种尺寸；强度 ±50 和 ±100。

- **坐标。** x、y 是圆心，y 自下而上；半径按画面短边计。
- **各向同性的径向移动。** 相对半径 ρ 处的源点向外移 D = i·A·ρ·(1 − ρ^a)^b 个半径，i 是原生强度（编辑器值 ÷ 100）。
  - 放大：(A, a, b) = (0.4, 3.25, 2.066)，圆心处放大 1 + 0.4·i 倍；
  - 缩小：(A, a, b) = (0.25, 5.40, 2.060)，圆心处缩成 1 − 0.25·|i| 倍。
  - 这两组参数在所有测过的半径、尺寸和横竖屏上都与原生相差 0.2 px 以内。圆外不动。
- **反解**同瘦身，12 步不动点迭代。

**三个工具的顺序**与原生一致：先拉长，再瘦身，最后放大缩小。

**没有复刻的部分：** 瘦身和放大缩小同样带着原生对整幅画面的亚像素重采样。横向同拉长；纵向还有约 1.0012 倍的缩放（H = 1280 时）。

## 一致性

- **合成坐标图（行映射）：**
  - 拉长时平均误差 ≤0.03 px，最大 ≤0.6 px。
  - 收缩时平均误差 ≤0.03 px，最大 ≤2 px。最大值出现在条带旁约 10 行的边缘过渡区。
  - 极窄区域收缩到几乎为零时除外。
- **原生审计照片（720×1280，±50）：**
  - 平均差 2.5–2.6 个色阶，p99 为 20；原生相对原图的平均改变量是 15–20。
  - 这个差值几乎都来自上面那个横向亚像素偏移：只要把 −0.5 px 补上，平均差就降到 0.7，p99 降到 4–5。
- **真实提供方与 Python 渲染器：** 两者输出逐像素一致（最大差 0）。常驻执行时每张约 0.6 秒。
- **瘦身，合成坐标图（去掉原生整幅重采样后）：** 14 个用例。每轴的平均有符号误差约为 0，平均绝对误差 0.03–0.14 px；二维误差 p99.9 ≤1.5 px，最大 1.85 px。最大值出现在 1280×720、强度 100、移动最多 55 px 的用例。
- **放大缩小，合成坐标图（同上）：** 13 个用例。每轴平均绝对误差 0.06–0.16 px；二维误差 p99.9 ≤1.22 px，最大 1.27 px。
- **原生审计照片（720×1280，+50）：**
  - 瘦身：自研与原生平均差 3.7 个色阶，原生相对原图的平均改变量是 5.8；把原生的整幅重采样补上，平均差降到 0.9。
  - 放大缩小：平均差 3.7，p99 为 27；原生相对原图的平均改变量是 5.9。
  - 也就是说，照片上的差主要来自没复刻的整幅亚像素重采样，而不是形变本身。

## 实现

**自研引擎**（`research/independent-beauty/`，已登记在 `source-manifest.json` 中）：
- `research/manual_body_render.py` 是 QCut 自有的渲染器，用 numpy 做双线性采样（拉长按行，瘦身和放大缩小按点）。回执包含：
  - 隔离证明；
  - 输入和输出的 RGBA 哈希；
  - 生效的工具和参数；
  - 有拉长时，每侧移动的像素数。
- `research/manual_body_slim_field.json` 是瘦身的形变表，登记在 `generatedFiles` 中，随引擎一起打包。
- `research/independent-pipeline-catalog.json` 新增 `manual-body` 阶段，位置在肤质 GAN 之后、脸部特征之前，和原生「先肤质、再手动美体、再脸型」的顺序一致。
- `src/independent-pipeline-plan.ts` 接受 `manualBody`：
  - 按编辑器的范围逐项校验：
    - 每个工具的强度都是 ±50；
    - 拉长：上线 ≥0.02，下线 ≤0.98，上下线间距 ≥0.02；
    - 瘦身：中心 0–1，宽高 0.02–1，旋转 ±180°；
    - 放大缩小：中心 0–1，半径 0.01–0.5。
  - 只保留非零的工具。没有生效工具时，规范参数里不出现 `manualBody`，所以旧的计划和回执不变。
  - 目录的 `manual-body` 阶段登记 `tools: ["stretch", "slim", "zoom"]`，规划器只接受目录列出的工具。
- `research/independent_pipeline.py`：
  - 计划校验按工具检查字段集合和取值范围；
  - 该渲染器支持原尺寸渲染。
- `research/independent_stage_runner.py` 登记了常驻执行的参数契约。

**Electron：**
- `beauty-lab-independent-manual-body.ts` 统一定义三个工具的 schema 和规范化规则（去掉强度为 0 的工具，−0 写成 0）。单张渲染、逐帧渲染和帧缓存键都用它。
- 帧缓存键按固定的工具和字段顺序加入手动美体参数；没有手动美体的请求，键和以前一样。
- `inspect()` 报告 `manualBodyTools: ["stretch", "slim", "zoom"]`。
- `beauty-lab-runtime-payload.json` 重新绑定了新的清单哈希。

**界面：**
- 时间线和美颜实验室的适配器把生效的手动美体工具原样传给引擎，只带引擎接受的字段。
- 引擎没列出的工具显示为「自研不支持：手动美体·瘦身／放大缩小」，预览和导出会报错，不会改用原生。
- 美颜实验室的状态行列出引擎支持的工具，例如「手动美体拉长、瘦身、放大缩小」。

**顺带修的导出路由问题：**
- API 导出判断「片段的美颜必须走渲染器」时，原来只看数值类参数。只有美妆、手动美体、手动精修或分人物设置的片段，在 auto 下会被送去 native，导出结果没有这些效果。
- 现在用 `electron/types/portrait-export-policy.ts` 判断。主进程运行时不能加载 `packages/`，所以这里是 editor-core `hasMediaPortraitAdjustments` 的镜像；镜像测试逐例比对，保证两者一致。
