# liblens：六个独立 CPU 数值原语（2026-09-07）

本轮交付 [independent-lens-contract](../../../research/independent-lens-contract/README.zh.md)：QCut 自行编写的 C++20 库、可直接运行的 CLI、数值测试、可选原生诊断源码。独立库包含实际矩阵、点变换和轨迹卷积算法，默认构建不加载供应商二进制或模型。

当前完成范围是 `LENS::ALGORITHM::MoveSys::Util` 中的六个原语。一次原生差分包含 **4,441 个案例、139,213 个数值，全部逐位相同**；三个新进程复跑得到相同统计，Debug 的 ASan/UBSan 构建也通过相同矩阵。这是固定版本、固定平台和已测输入域的数值结论，不是完整视频防抖或防闪烁的验收。

## 精确算法语义

### 1. 3×3 矩阵乘法

入口 `MatrixMul3x3`：arm64 `[0x95830,0x95f38)`，三个参数分别是左矩阵、右矩阵、输出矩阵，元素均为 double，按行排列。

它没有按普通三层循环累加 27 次乘积，而是计算 **23 个乘积**，再按固定顺序相加。独立源码 [matrix.cpp](../../../research/independent-lens-contract/matrix.cpp) 保留这套表达式顺序。例如输出左上角按 `(a00*b00 + a02*b20) + a01*b10` 计算；浮点舍入顺序可观察，不能只按代数等价改写。

1,000 对有非二进制分母的确定性随机矩阵得到 9,000 个输出，全部逐位相同。单元测试另检查行排列、左右乘法顺序、整数已知解和输出别名。

### 2. 3×3 求逆

入口 `MatrixInv3x3`：arm64 `[0x95f38,0x9622c)`。

行列式使用第一行展开：

```text
det = a00*(a11*a22-a21*a12)
    - a01*(a10*a22-a12*a20)
    + a02*(a10*a21-a11*a20)
```

先计算 `1/det`，每个伴随矩阵元素再乘这个倒数，写出顺序按行排列。不能换成每个元素直接除以 det。

原生代码没有零行列式、非有限值或输入输出重叠保护。QCut 接口增加有限数值与结果检查，零行列式直接拒绝；使用临时结果后发布，支持自有输入输出别名。保护域内的 1,000 个对角占优矩阵得到 9,000 个逐位相同的结果。这里没有用这些样本证明极端病态矩阵的数值稳定性。

### 3. 点旋转

入口 `Rotate`：arm64 `[0x976bc,0x97780)`，输入点使用 float，参数依次是角度、中心 x、中心 y。

计算顺序是减中心、乘旋转矩阵、加中心。角度转换使用 float 位模式 `0x3c8efa39`，数值为 `0.017453299835324287`；再分别调用系统 `cosf` 和 `sinf`。因此 `(1,0)` 绕原点转 90 度的结果为 `(-6.3975784314607154e-7,1)`，不能用理想零或另一份 π/180 常量替代。

旋转矩阵为 `[cos,-sin; sin,cos]`。坐标属于输入点所采用的坐标系；未通过像素读回证明屏幕上下方向，因此本轮不额外给它标注屏幕顺/逆时针。

### 4. 刚性点变换

入口 `WarpPts`：arm64 `[0x97a6c,0x97b0c)`。静态代码仅读取 Rigid 参数的前 16 字节，四个 float 位于偏移 `0/4/8/12`；本轮分别恢复为平移 x、平移 y、角度、缩放。

```text
q = input - translation
q = Rotate(q, degrees, center=(0,0))
output = q * scale
```

没有把平移加回，也没有齐次坐标除法。零缩放会把点收拢，负缩放仍可计算。独立入口处理坐标列表，不分配或采样图像，不代表完整帧 warp。

旋转和刚性点变换分别验证了 300 组、18,680 个坐标值，覆盖空列表、多个列表长度、非零中心、正负角度和平移、正负缩放；结果全部逐位相同。

### 5. 高斯核

`Gauss` 位于 `[0x982b8,0x98360)`；`GaussKernel` 位于 `[0x98360,0x98630)`。核元素为 double。

权重函数按原生顺序计算：

```text
g(sigma,x) = (1 / sqrt(6.2831854820251465 * pow(sigma,2)))
             * exp(-1 * (pow(x,2) / pow(2*sigma,2)))
```

指数分母为 `(2σ)²`，并非 `2σ²`。`6.2831854820251465` 是二进制里实际存储的 double 常量。

对于奇数长度 n，令 `r=(n-1)/2`；对于偶数长度 n，令 `r=(n-2)/2`。非零采样位置间隔为 `3σ/r`，负半边从 `-r` 走到 `-1`，随后中心，再走正半边。偶数长度把中心插入两次。长度 1 输出 `[1]`，长度 2 输出 `[0.5,0.5]`。最后按顺序求和，并让每个权重除以总和。

长度 3、sigma 1 的核为：

```text
0.087049355438259091  0.82590128912348182  0.087049355438259091
```

核的采样位置同时随 sigma 缩放，因此在精确实数运算下，归一化后的形状不随 sigma 改变。浮点运算仍会有末位差异，源码没有把 sigma 当成无用参数删除。

### 6. 轨迹平滑

`GaussSmooth(vector<float>&,int,double)` 位于 `[0x9883c,0x98a34)`。

输入 float 升为 double，逐点按核顺序相乘并累加，边界位置 clamp 到首/尾样本，最后仅在写出结果时转回 float。所有输出算完后才替换输入；不是边算边更新的递归滤波。

原生平滑以 `r=length/2` 遍历 `2r+1` 个核元素。偶数长度的 kernel 只有 length 个元素，因此平滑会索引到 `kernel[length]`；本轮没有对这个越界域发起原生调用。QCut 的 smooth 接口明确拒绝偶数窗口，kernel 接口仍支持偶数核。

kernel 覆盖长度 1..65 和七个 sigma 值，共 455 案例；smooth 覆盖其中全部 33 个奇数长度、七个 sigma、六种输入长度 `0/1/2/7/31/257`，共 1,386 案例。窗口可宽于输入，空输入返回空输出。

## 编译优化也是合同的一部分

首轮实现遇到两项真实差异，均保留证据，没有通过放宽阈值处理：

1. 编译器把 `pow(x,2)` 换成 `x*x`，长度 13、sigma 0.7 的核出现约 `3.5e-18` 差异。静态代码经 helper 调用系统 `_pow`；恢复真实函数调用后全部 kernel/smooth 通过。
2. 编译器把两个三角函数合成 `__sincosf_stret`，一个随机旋转坐标从原生 `-719.4432373046875` 变成 `-719.44329833984375`。恢复分开的 `_cosf`/`_sinf` 后通过。

独立代码使用函数指针防止这两种替换；CMake 关闭浮点乘加收缩和 fast-math，公共头也拒绝手工启用 fast-math 的编译。不存在把误差统计写成零的容差补丁。当前诊断会拒绝任何位模式不同的结果，包括数值相等的正负零；最终不同位模式与最大绝对误差都是零。

- Release CMake 构建：`-Wall -Wextra -Wpedantic -Werror`，通过。
- Release 和 Debug ASan/UBSan：CTest `2/2`，通过。编译和链接均设置 `-fno-sanitize-recover=all`；MSVC 请求这一未配置的 sanitizer 组合时，CMake 直接失败。消毒器覆盖自有源码；供应商库本身没有重新插桩。
- 三个独立新进程执行完整原生矩阵，结果 JSON SHA256 都为 `9d4839dc8e57aab391bc91f973673affeb58cf7cff717b511fa72bef4509aff6`。
- 消毒器版本再次执行完整原生矩阵，所有数值仍逐位相同。
- CLI：六种模式各一项成功验收，以及十项缺失/非法/超限/多余输入拒绝，共 `16/16`。
- 原生诊断对错误 SHA 文件返回 `1`，标准输出为空，明确报告没有进行原生调用。
- fast-math 编译负控被公共头拒绝；私有的故意 signed-overflow 程序被 UBSan 检出后立即以 SIGABRT 终止，没有打印后续内容。
- `otool -L lens-contract` 只显示 `libc++` 和 `libSystem`，没有供应商库依赖。

普通库和 CLI 的核心实现只使用标准 C++。可选诊断先验证文件 SHA，再验证加载映像 UUID；所有供应商日志与 JSON 输出分开。调用在新进程中完成，没有运行剪映界面、修改草稿或注入应用。
