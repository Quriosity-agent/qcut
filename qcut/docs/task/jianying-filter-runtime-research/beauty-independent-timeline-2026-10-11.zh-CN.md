# 自研美颜接入时间线

日期：2026-10-11。分支：`beauty-video-timeline`，起点 `8a9e44ffd`（v2026.10.11.2）。
工作目录：仓库内的 `qcut/`（本文其余路径均以它为基准）。
前置记录：[原生冷启动对照与残差更正](beauty-lab-cold-native-2026-10-11.zh-CN.md)。

## 结论

时间线上的每个片段现在可以在「原生 / 自研」之间选择美颜引擎。选自研后：

| 场景 | 行为 |
| --- | --- |
| 暂停预览 | 用自研处理当前帧，处理中在画面左上角显示提示 |
| 播放 | 视频片段显示原画面，不调用引擎；图片片段照常显示处理结果 |
| 导出 | 逐帧用自研处理，显示进度，可取消；处理过的帧写入磁盘缓存，再次导出直接复用 |
| 参数不支持 | 预览弹出原因并显示原画面，导出在第一帧之前就停止；都不会改用原生 |

速度暂按现状接受，界面已标明：每帧约 3–12 秒，参数越多越慢。性能是下一步。

## 使用

人像属性面板「原版美颜美体」开关下方新增「处理引擎」选项，默认原生。选自研后面板显示：

- 说明：每帧约 3–12 秒；播放显示原画面、暂停显示结果、导出逐帧并缓存；最长边 1280；竖屏 9:16 暂不支持磨皮和美白。
- 自研引擎未就绪时的原因。
- 当前参数里自研不支持的项（按面板上的中文名列出），或需要先清除的单人设置、手动精修、手动美体。

## 设计

**数据**：`portraitAdjustments.engine`。缺省即原生，normalize 只保存 `"independent"`，未选择过引擎的项目存储内容逐字节不变。剪映草稿导出的快照校验接受这个字段；草稿本身仍由剪映原生渲染。

**主进程**（`electron/beauty-lab/`）：

- `beauty-lab-independent-queue.ts`：自研引擎一次只跑一个任务，原来第二个调用方会直接收到「busy」。现在美颜实验室、暂停预览和导出共用一个队列，按到达顺序执行；每个调用方都能按 requestId 取消自己的请求，无论是在排队还是正在运行。
- `beauty-lab-independent-frame-cache.ts`：按内容寻址的磁盘缓存，位于用户数据目录的 `Cache/independent-beauty-frames/`。
  - 键由引擎版本、处理尺寸、参数（键名排序）和输入像素共同决定。引擎版本取源码清单哈希加外置运行库清单，换了引擎就不会读到旧结果。
  - 每条记录是 PNG 加一份校验记录（PNG 与 RGBA 的 SHA-256）。读取时任何不一致都按未命中处理，并删除该条。
  - 超过 4 GB 时按最近使用时间淘汰。
- `beauty-lab-independent-frames.ts`：时间线帧专用的 IPC `beauty-lab:render-independent-frame`。先查缓存，未命中再走队列调用引擎，然后写入缓存。缓存写失败只记日志，不影响这一帧。
- `beauty-lab-independent-services.ts`：集中组装引擎路径、队列、缓存和帧接口，`main.ts` 只留一处调用。

**渲染端**：

- `independent-portrait-adjustments.ts`：把片段参数转换成引擎请求。
  - 只发送非零参数和强度大于 0 的妆容。
  - 关闭肤色后，肤色强度两项与原生一样忽略。
  - 单人或分人物设置、手动精修、手动美体都作为问题返回，不会悄悄丢弃。
- `independent-portrait-frame.ts`：
  - 把帧变成不透明再交给引擎，处理完恢复原来的透明边（预览中「适应」留下的边）。
  - 取消信号会终止引擎进程。
  - 引擎报错去掉 IPC 包装和 Python 调用栈，只保留最后一条异常；皮肤分割比例问题直接给出中文说明。
- `portrait-processing-size.ts`：自研的处理尺寸缩到最长边 1280 以内，绘制时再放大回目标尺寸。
- `browser-color-rendering.ts`：在人像处理入口按引擎分流。自研路径的错误向上抛出。
- `color-preview-canvas.tsx`：
  - 播放中视频片段不调用自研。
  - 播放／暂停切换和跳转会放弃正在处理的旧帧，处理最新的一帧。
  - 失败时提示原因并显示原画面。
- `export-independent-portrait.ts`：导出开始前检查所有用到自研的片段（包括复合片段里的子片段）：引擎是否可用、参数是否都支持。导出进度文字标明正在用自研逐帧处理。

## 限制

- **画面比例**：本快照的皮肤分割模型只有 5 种输入尺寸：128×128、128×144、128×160、128×176、224×128。竖屏 9:16 画面换算为 128×224，不在其中，所以用到这个模型的磨皮和美白不可用；16:9 和 3:4 可用。
  - 在本机对同一帧直接调用引擎验证：9:16 下磨皮、美白失败；瘦脸、瘦鼻、大眼、祛痘、肤质、轮廓平滑和口红都成功。
  - 裁成 3:4 后，磨皮、美白、瘦脸、瘦鼻、大眼都成功。
- **分辨率**：最长边 1280。1080p 导出会缩小处理再放大，整帧会变软。
- **人脸**：只能对全部人脸统一处理。
- **跨帧**：每帧独立检测，没有跨帧跟踪和平滑。引擎目录本身注明「视频、多脸及其他 GPU 未验收」。
- **速度**：每帧单独启动一次 Python 处理进程。本机直接调用引擎实测：
  - 单项参数约 3 秒一帧；
  - 磨皮、美白、瘦脸、瘦鼻加口红五项组合约 10 秒（480 高）到 11.4 秒（1280 高）一帧。

## 验证

单元测试：

- editor-core：引擎字段的保存与 normalize。
- 主进程：队列、帧缓存（命中、引擎更新后失效、损坏条目、尺寸校验、写失败、淘汰）、IPC 通道。
- 渲染端：参数转换、逐帧调用（透明边、取消、错误信息）、处理尺寸、导出前检查、引擎选择组件。
- 剪映草稿快照：引擎字段校验。变异检查：去掉取值校验后测试失败。

真实 Electron E2E：`apps/web/src/test/e2e/portrait-independent-timeline.e2e.ts`。

- 输入：本机一段 360×640、24fps 的真人视频，不提交。它的样本宽高比为 171:176，浏览器按 360×659 显示。
- 环境：后台模式，独立的用户数据目录。
- 用时：1.1 分钟，通过。

| 步骤 | 结果 |
| --- | --- |
| 9:16 画布上设美白 45 | 弹出「暂不支持这个画面比例」，显示原画面，没有写入缓存 |
| 暂停，大眼 60 | 先出现「处理中」提示，随后显示自研结果。与按同样「填充」方式缩放的原帧相比，775 个像素（0.34%）不同，全在第 100–143 行的眼部。预览画布与缓存里的引擎输出逐像素一致（调试时核对） |
| 播放 0.8 秒 | 画面继续刷新；没有处理提示，没有新缓存，没有引擎进程 |
| 暂停在新的一帧 | 处理这一帧，缓存增加到 2 条 |
| 冷导出 0.25 秒（8 帧，1080×1920 输出，在 720×1280 上处理） | 25.5 秒，约 3.2 秒一帧。新增 7 条缓存：第 0 帧命中了暂停预览存下的同一帧 |
| 再次导出 | 0.54 秒，没有新增缓存。两次导出的逐帧 MD5 一致 |
| 改成大眼 70 后导出并中途取消 | 取消前处理了 1 帧；取消后引擎进程在 15 秒内退出，之后 15 秒没有新缓存，也没有输出文件 |

E2E 截图、导出视频和证据 JSON 在 `output/playwright/portrait-independent-timeline/`，不提交。

调试中发现的两个测试问题，都不是产品缺陷：

- 没有美颜数值时预览不挂调色画布。
- 对照图起初没有按视频的显示尺寸做「填充」，整帧都算成了差异。

## 仍未完成

- 竖屏比例的皮肤分割、最长边超过 1280、跨帧稳定：独立版仓库在快照之后已有相关改动，需要同步引擎快照。
- 编辑器暂停预览的原生跟踪确定性、干净 Mac 安装与 notarization、研究项 P1–P3，状态不变。
