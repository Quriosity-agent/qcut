# 独立美体：运行中重置、多人规则与显式蒙版，2026-10-19

本轮延续跳时／RESET_PARAMS 原生热重置，补齐运行中尺寸变化、默认多人选择及显式宽肩蒙版。独立侧从原图自行运行感知、状态与渲染；原生数据只作后续对照。固定范围为已钉住版本的 upright / modern CPU / 默认单身体目标配置。代码不调用剪映原生库，但推理仍需要本地私有模型权重。

## 运行中完整重置与尺寸变化

跳时和 RESET_PARAMS 沿用原包时间阈值与字段重置规则；不把所有模型、跟踪对象和历史一起重建。离线 manifest 现在可逐帧传入 `control_events`，事件按序应用到该帧的显式 `controls` 基线；不会暗中继承上一帧的 controls。

尺寸变化分三层处理：

- 算法图：原生关闭 `enable_fix_algorithm_resolution_change_twice`，源尺寸改变的首帧使用 128×224 请求，下一帧回到 360×640 请求。要求收集和图像生产各做一次同样的 float32 比例计算与整数截断，面积条件会直接保留源尺寸。不能用一次 Python double 比例乘法代替。例如 3342×1235 的稳定算法图是 974×360，旧式计算会错成 974×359。两个真实原生函数联合 65,548 例一致；当前生产资源边界接受的 52,585 例全部一致，其余 12,963 例明确拒绝超预算尺寸。
- 身体：算法图尺寸改变时清除当前活动追踪点与迭代计数，当帧重新 coarse，保留网络和外部连续帧计数。coarse 仍只种下目标，不伪造外部身体。
- 活跃人脸：缩放 raw106 跟踪点，保留 ID、年龄、tracking filter 和变换历史。该次成功的120对齐重建 Base 与当前姿态；按原生宽高比例差区分等比和非等比变化。非等比失败时保留原生两次 detector 调用顺序，不替换成冷重启。

组合网格按新源尺寸重置原生规定的字段，同时保留当前强度、肩部计数相位、需保留的滤波存储和已锁存蒙版。快照版本提升为5，旧版在修改运行中会话之前拒绝，避免把旧选人策略或不完整历史混入新会话。

- 24帧全身原图序列：1080×1920、720×1280、1280×720切换，感知、base/UV、最终网格、十部位状态、肩部 cache 和 RGBA 全部一致。
- 另24帧活跃人脸序列：包含同方向换分辨率和改变宽高比，全部原图感知、240个累计阶段网格与最终 RGBA 一致。72份稀疏位移历史数值一致，5份存在正负零的字节差；不把它称为72份逐字节一致。

### 算法图的实际绘制拓扑

奇数宽度对照还发现算法图的四边形对角线不同。原生实际调用 `glDrawArrays(GL_TRIANGLE_FAN, 0, 4)`，顶点按左下、右下、右上、左上排列；转换到独立 Metal 的设备坐标后，使用左上到右下的对角线。旧独立视频算法图使用另一条对角线，float UV 插值会在少量量化边界产生一字节差异，不能通过任意 shader 偏移修补。

捕获真实 shader、顶点、UV、纹理与采样状态后，以原拓扑重放：555×777→457×640 原有23个不同像素、641×650→631×640 原有18个不同像素，均变为逐字节一致。观察 hooks 的39份原生 RGBA 与未加观察的基线一致。此次只更正显式算法尺寸的视频路径；默认照片路径保留原有绘制行为，不把视频证据扩写为照片路径原生验收。两项无需模型的回归测试钉住视频 fan 的展开顺序、坐标方向、采样策略和默认照片行为；原始证据保存在 `native-mask/algorithm-gl/`。

## 显式蒙版分支

当前原包没有启用自动人像分割。未修改的 algorithmConfig 没有 Matting 节点，原包完整 graph 的 36 帧捕获中，Public 蒙版指针始终为空，两种肩部对象的 maskEnabled 始终为 false，输入字节为空。这次补齐的是原生实际存在的 **WidenShoulder 显式 MattingResult 输入**，不把它扩展成所有部位的通用保护 alpha。

原生 Public 从算法结果 key12 读取 MattingResult；宽肩 prepare 复制二维 uint8 数据、宽高和启用标记。正肩 prepare 没有读取这一输入，其几何内部的蒙版分支尚未找到当前原包的启用来源。本轮不虚构正肩蒙版开关。小头／手臂旧研究状态中的 `protection` 命名也不是分割：对应原生 needSmooth，已由独立跨帧位移历史处理。

### 还原的规则

- 输入是 top-down 字节图，网格是 y-up。按原生 float32 次序执行带 `1.01`、`-0.01` 偏置的最近邻向下取整，再做一次四邻域十字膨胀；不做对角膨胀。
- 任意非零字节都表示内部，1 与 255 等价，不是连续透明度。
- 蒙版内部使用宽肩原完整半径和方向衰减；外部使用 0.2 倍半径并关闭该方向衰减。因此全零蒙版也不等于零变形。
- 跨帧原始位移融合使用原生启用蒙版系数，并将外部融合权重降为内部的四分之一。保留原有浮点次序、15 次调用的边界收缩和空间平滑。
- 本帧没有 MattingResult 时保留上次复制的蒙版；热 IMAGE／跳时重置也保留。明确供应新蒙版才替换；重建独立流才清除。没有发明清空蒙版的原生事件。

### 接口

`BodySmartSequence.process(..., segmentation_mask=mask)` 支持二维 `numpy.uint8`，入口复制为连续自有数组，经过持久组合传给宽肩。`None` 表示没有新输入，继续使用已锁存蒙版；这和全零数组不同。checkpoint 保存锁存数组；完整流 reset 清除，原生热 reset 保留。

离线 manifest 每帧可选：

```json
{
  "image": "/absolute/frame.png",
  "timestampSeconds": 0.03333333333333333,
  "controls": {"WidenShoulderTest": 25},
  "segmentation_mask": "/absolute/body-mask.png"
}
```

路径必须绝对；文件必须是单帧、8 位、单通道 `L` PNG，不隐式采用 RGB、alpha 或 16 位数据。`null`／省略继续保留旧蒙版。所有路径与图片头在初始化模型前预验，每帧再解码其蒙版，不预加载整批 300 张数组。单轴上限 16384、总像素上限 16777216 是自研资源边界，不是原生算法阈值。

## 原包默认多人选择与追踪

原包默认只追踪一个身体。它的 coarse 检测可以产生多个候选，但候选先经过关节有效性筛选，再按解码顺序保留第一个；没有按最大脸、最近人物或总置信度另排顺序。历史 `SK_SetTargetNum(2)` 研究属于显式自定义目标数，不是原包默认。

具体筛选统计 `valid != 0` 且 `score >= 0` 的关节，至少八个才能成为 coarse seed。零分有效点计数，NaN 不计数；refine 仍采用其原有任意有效点规则，不能把八点门槛套到追踪阶段。照片与视频入口共用这一选择函数。真实原生 `pruneFalseAlarm`→`filterTargetsOpt` 与自研规则在 1000 组带有效位、负分、零分、NaN 的合成候选上全部一致。

已有目标有效时持续 refine，不重新检测新入场人物。目标丢失后下一帧 coarse，内部重新种下 ID0，但 seed 帧不发布外部身体；随后 refine 成功才发布。ID0 会被新候选复用，不能解释为外观重识别。算法图尺寸改变会清理活跃追踪对象与迭代状态，当帧重新 coarse，并保留网络实例。组合系统的方向复位比较第一条身体结果的 orientation 字段，不比较 person ID。

### 检测器缩放的浮点边界

扩大尺寸矩阵后，第20帧（359×1001算法图）发现检测矩形已经不同，差异发生在人脸160×160对齐输入裁剪之前。原生 `FaceDetectorModel::DetectFace`（liblens arm64 `0x33581c`）调用 resize，BGR 专用分支 `0x263e4c` 在 `0x263f98..0x2640e0` 构造横纵坐标表：先以 float32 求目标尺寸倒数，再对 float32 中心坐标与源尺寸乘积执行 FMA 半像素减法；小数权重量化到128份，逐轴截断。旧独立实现用 double 直接相除，在1001→896的半权重位置产生不同舍入，导致该帧检测输入5479个像素不同、最大通道差2。

新增 `detection_resize.py` 还原此次序，仅替换检测器预处理。原有对齐采样、vendor 通用实验函数不变。五项新增测试覆盖半权重、边界复制、先横后纵截断、非连续输入与输入所有权、非法尺寸；与原有检测器契约测试合计17项通过。

使用同一原生算法图单独隔离检测器预处理，47次真实调用的BGR模型输入全部逐字节一致。该诊断明确使用捕获的算法图，不能当作独立原图推理验收；报告位于 `native-resize/face-audit/detector-preprocessing47-exact.json`。修正前一级算法图 raster 的三角扇对角线后，从独立原图生成的算法图再经生产检测器预处理，47次输入同样全部字节一致，见 `detector-preprocessing47-independent.json`。原生库、薄切片、候选源码hash和每次调用尺寸均写入报告。

### 同分候选的真实排序

严格核验被拒绝的人脸候选时，尺寸矩阵第21帧第四个候选仍有差异：原生框为 `[154,92,7,6]`，旧自研为 `[154,92,8,7]`。两者都会被后续160模型拒绝，因此此前全部发布感知、网格与最终像素相同，但这不能代替内部规则一致。完整原生图的47次检测输入经过独立网络后，全部排序前 proposals 均逐字节一致，差异只出现在第21帧31个候选中的同分顺序。

原生 `Box::operator<`（liblens arm64 `0x34fec0`）只比较 score 大于，没有坐标或面积 tie-break。`__sort`（`0x34efb0`）采用小数组交换／插入排序，长度超过30进入分区，达到1000采用五点采样；分区交换决定同分候选的次序。NanoDet 调用点 `0x34a5ec..0x34a6a8` 还明确区分候选数：小于 `before` 时完整排序，大于或等于时调用 `__partial_sort`（`0x35005c`），随后截断并做NMS。默认 `before=1500`，恰好1500也走堆排序，不能把完整排序后截断当作等价实现。

自研 `detection_order.py` 按上述规则重建索引排序，保持输入不变，不调用系统或原生排序。独立真正原生 oracle 验证完整排序951组／533345元素、部分排序1190组／1955792元素，全部保留元素与次序逐字节一致；包括全同分、离散随机、连续随机、正逆序、单异常、30／31、999／1000、1499／1500／1501以及20000候选。真实完整图的47次排序同样一致。六项新增测试使用无模型的合成输入与原生黄金次序，覆盖上述阈值、输入所有权和NMS实际采用排序结果，与检测器其他测试合计23项通过。

排序证据为 `native-mask/detector-sort/` 的原生与自研 corpus 收据、`native-identity/detector-sort47-comparison.json`，以及 `native-resize/face-audit/formula2-face/` 的真实图排序与 proposals 对比。被捕获的原生输入仅用于定位单个阶段；最终原图对拍由生产入口独立重新推理。
