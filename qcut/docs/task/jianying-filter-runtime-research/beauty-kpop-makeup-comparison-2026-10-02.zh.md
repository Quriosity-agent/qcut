## 差分方法与目视结论

并排列为：剪映零值参考、剪映改后、剪映灰度差分、QCut 改后、QCut 灰度差分。QCut 原始输入/零值在单项子目录中单独保存。

各端分别计算自己的 `mean(abs(Gaussian(改后)-Gaussian(零值)), RGB)`，σ=0.6，统一线性增益 ×6，超过 255 封顶。QCut 基线与结果以同样的 Lanczos 缩放至剪映播放器尺寸。未逐张自动增强，未做几何配准。黑色表示没改或变化小，亮色表示变化幅度大，不表示效果更好。

| 部位 | 本轮实际观察 | 仍需验证的差距 |
| --- | --- | --- |
| 氧气感 | 两端都主要改变嘴唇、眼周与面部修容区域，整体接近 | 眼周/鼻侧的细轮廓与纹理仍有残差 |
| 两款口红 | 改动集中在同一唇部，色调及外轮廓接近 | 唇缘颗粒、局部亮度与细节不能判定逐像素一致 |
| 六款眉妆 | 六款各自真实运行，作用位置、眉弧及样式变化接近 | 眉头/眉尾、毛流贴图仍存在细节差异 |
| 腮红、修容、高光 | 主要面颊、鼻梁/鼻侧区域接近，没有明显错贴到背景 | 局部覆盖和柔化边缘有差别，JPEG 噪声影响亮度判断 |
| 卧蚕、睫毛、眼线、眼影 | 大体在正确眼周区域生效，猫眼尾部方向接近 | QCut 部分细线更集中、更清晰；剪映差分更分散，卧蚕细轮廓尤其不相同 |
| 美瞳 | 变化集中于双眼虹膜 | 虹膜边缘与局部纹理尚未通过同规格无损导出判定 |
| 雀斑 | 两端都主要作用在双颊及鼻侧 | 颗粒分布与局部细节残差仍可见 |

`paired/report.json` 的 RGB 平均变化是诊断数，不是接近程度评分。剪映 JPEG 与 QCut PNG 的编码及采样不同；不能通过平均值比例调整强度，也不能把截图噪声判成算法错误。本轮没有修改强度映射或更换原生运行库。

UI 已检查 QCut 1280×800 和 1800×1100 两种窗口：分类自动换行、卡片保持方形，所有按钮位于面板内，均无横向溢出。缩略图分别约 47.14px 和 64px。分类名称、程度控件和卡片方式接近剪映，但 QCut 当前每类可选素材明显少于剪映，不宣称 UI/素材库完全一致。

### 同款效果相差多少

`compare-portrait-feature-makeup.py` 新增 `signedDeltaMetrics`，复用已有鼻部对照工具的 `delta_metrics`，分别报告全画幅与固定脸部裁剪 `[215,65,555,475]`，均使用 σ=0.6。各端先减自己的零值，然后比较带正负方向的 RGB 改动：

```text
Dj = Gaussian(剪映改后) - Gaussian(剪映零值)
Dq = Gaussian(QCut改后) - Gaussian(QCut零值)
deltaCosine = dot(Dj, Dq) / (norm(Dj) * norm(Dq))
deltaMae = mean(abs(Dj - Dq))
```

余弦反映改动位置、颜色方向和相对分布是否一致，不等于像素相等率；同方向的幅度差由 MAE 补充。相同绝对亮度但相反颜色方向不会被误判为一致。零改动不产生方向分数。脸部 MAE 的单位是 0–255 RGB 码值，仍会被局部效果的稀疏性稀释，不能单独作为验收。

这些数值来自真实 19 组截图与编辑器画布，输出于 `paired-quantified/report.json`。较大改动的口红/修容方向比较一致，细眼线、美瞳、雀斑的残差更值得优先排查。但它们同时受到 JPEG 4:2:0 编码、预览缩放和运行条件影响；尤其微弱眼周效果，不能将 `1-cosine` 写成「还差百分之多少」，也不能拿两端平均改动幅度的比值乘强度。

### 原理和实现

美妆链路是本地人脸检测/关键点模型与原生素材渲染，不是通过提示词重新生成整张脸。配置中的 `tt_face_extra`、`tt_fsnew_base_jianying`、`tt_freid` 提供相关人脸算法与人物追踪能力，效果包中的 prefab/贴图及渲染逻辑决定具体妆容；没有重写供应商模型内部算法。

1. `makeup-catalog.ts` 登记卡片的分类、资源 ID、精确版本、原生参数键和默认程度。新增九款都核对了实际 `config.json` 的 `composer_param`，默认 `0.8` 对应 UI 的 80。目录中的 `extra.intensity_key` 可能有错拼或前导空格，不能只凭名称或元数据猜接口；本轮以同版本包配置为准。
2. `makeup-resolver.ts` 沿用私有缓存优先、已安装剪映缓存次之的查找逻辑，要求 `config.json` 与 `makeup.prefab` 实际存在。封面与渲染包独立解析，只有封面不能冒充效果就绪。缺包在 UI 中禁用。
3. `PortraitMakeupControls` 沿用现有四列方形卡片与程度控件，按后端目录显示新款。同类替换、跨类保留，数值 0 保留选择但不排渲染，选择“无”清除该分类。新加款式不需要另一套 UI 或渲染器。
4. `stages.ts` 把选中动态妆容装入已有 makeup 基础阶段。`buildJianyingDynamicMakeupParameters` 发出 `{参数键: [{id, intensity, path}]}`，程度只除以 100 一次，素材路径指向该精确版本。逐脸参数用追踪 ID，不能把每个包独立检测出的 ID 当成同一个人。
5. `provider.ts` 经独立原生宿主处理同尺寸 RGBA，返回实际像素给预览与导出；按源帧、参数和追踪范围缓存。没有叠加手画眼线、全局模糊或经验乘数来追截图。

本机九个新增包均解析为 `jianying-installation`，原来三个卧蚕/眼线包为 `qcut-private`。没有把新增包复制进私有包清单，未证明私有缓存独立部署；实际开启 `QCUT_JIANYING_DISABLE_USER_CACHE=1` 复查，新增九款均为 `source:none`、`ready:false`，原来三款仍就绪。资源、模型、封面和输出图片都没有提交进 Git，也未承诺 Windows/Linux 或无剪映安装用户可以直接使用。
