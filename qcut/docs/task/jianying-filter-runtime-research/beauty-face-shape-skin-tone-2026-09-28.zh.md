# 脸型与肤色：逐项对照及缺口

日期：2026-09-28。分支：`beauty-kpop-v2`。产品基线：`5df3de30fd58ef7dd8edad09499b9e613ed5e7c5`。

本轮覆盖用户截图中的13个脸型控件、5个肤色色板。只增加测试、对照工具和文档，未更改美颜算法或产品UI。承接[祛斑祛痘输入分辨率修复](beauty-blemish-resolution-2026-09-28.zh.md)，没有将该修复的放大策略直接套到脸型上。

后续更新：下颌骨已通过原生策略开关缩小差距，同规格真实导出 50/100 两档的差分 MAE 下降 25.1%/35.8%，见[下颌骨修复与导出验证](beauty-jawbone-strategy-2026-09-28.zh.md)。下文保留修复前的截图诊断数据，不能作为修复后现状；其他缺口不变。

## 结论

- **9项较接近**：瘦脸、窄脸、颧骨、短脸、V脸、下巴长短、下庭、中庭、上庭。在本照片、所测档位上，改动范围和方向较吻合，不是全素材精度验收。
- **1项仍有范围/强度差异**：下颌骨。QCut在画面左侧轮廓的改动更明显，整体改动幅度偏高。
- **2项明显不一致**：流畅脸、下颌线。不是只差一点强度，变化集中位置也不同，优先检查UI命名与运行参数映射。
- **1项缺入口**：小脸。QCut已有的 `face_adjust_SmallFace` 对应“短脸”，本轮与剪映短脸很接近，不能仅凭英文key把它重命名为“小脸”。
- **5种肤色色板未接齐**：QCut只有肤色强度和冷暖，当前没有用户可选择的五色色板。本轮分别记录五种剪映效果，也记录QCut现有肤色，不伪造一对一映射。

功能E2E通过与视觉对齐是两套结论：当前测试确认控制、渲染、复位、保存重开、组合导出可用，但明确发现上述视觉与UI差距。

## 代码与UI差距

- `electron/jianying-portrait-adjustment-runtime/catalog.ts` 中，“流畅脸”使用features包的 `face_adjust_temple`，“下颌线”使用 `face_adjust_jaw`。代码确认目前映射，视觉证据提示与当前剪映UI语义不符；**还没有证明剪映正确的包/key/组合参数是什么**。
- 同文件中 `face_adjust_SmallFace` 的中文是“短脸”，本轮验证支持此映射。缺失“小脸”应该单独追踪，不能覆盖短脸或将两者共享同一参数。
- QCut实测脸型顺序是瘦脸、窄脸、V脸、下颌骨、颧骨、下巴长短、尖下巴、短脸、发际线、流畅脸、颧弓、下巴、下颌线、下颌角、上庭、中庭、下庭，与截图顺序不一致。额外控件本轮未全部验证。
- `advanced-controls.ts` 仅定义肤色强度 `face_adjust_skin_Intensity` 与冷暖 `face_adjust_skin_ColdWarm`，均走固定skin-tone包，没有五色选择契约。
- 当前固定包版本：face为 `7408077448513998114/aa4932200616e291a252039a3aac7232`；features为 `7408077472211668276/f662ff9c955ee319f1ae03b2aa27df76`；skin-tone为 `7408757645705760000/c36221f2a2097535ce1a2f70cd9e0116`。有包、有同名事件不等于新剪映UI语义一致。

## 下一步顺序

1. **先下颌线，再流畅脸**：各做一次参数前后草稿/资源引用取证，确定当前剪映真实包、事件key和是否多参数组合；用同源浏览器输入的原生探针逐个候选隔离验证。不要仅改中文名、整体放大系数或直接沿用祛斑的分辨率策略。
2. 找到可验证入口后，先整理UI顺序与名称，再修运行路由；保留已有项目参数兼容，避免同一个持久化key静默改变语义。对照图同时保留旧QCut、新QCut和剪映。
3. 独立追踪“小脸”，补单独契约/控件与渲染映射，同时保留已经验证较接近的“短脸”。
4. 追踪五个肤色的真实资源/颜色参数：确认是不同包、LUT还是uniform之后再选实现；使用色块选择控件，支持“无”、强度、冷暖、复位、保存重开，不能只摆五个色块但仍调用同一个固定效果。
5. 下颌骨增加无遮挡正脸，分离左右区域与强度差异。至少再补一张脸、一段运动视频及两个应用同规格导出，然后才能提高精度验收等级。
