# 五官精修与美妆对齐记录

日期：2026-09-30 至 2026-10-01。分支：`codex/beauty-kpop-v3`。

## 结论与验收边界

这轮完成了六个缺失五官算子的实际接入、鼻子和眉毛的 UI 对齐、美妆分类和强度交互修复。不是仅增加滑杆：新增算子已经通过真实 QCut 编辑器画布执行。

- 27 个标准五官项，每项两个非零档位，每张真人有 54 个独立画布案例。
- 12 个美妆分类，目前选择了 15 张本机已有效果包的卡片；不等于剪映完整美妆素材库。
- 三张真人的最终完整链路均通过：162 个五官案例、45 次美妆应用和封面解码检查、三段导出合计解码 90 帧；不是 45 张不同美妆卡片。
- 六个新增算子各有剪映 50/100 档截图，另有珊瑚裸粉同值截图，共 13 组配对证据。
- 真实视频导出已经解码；剪映参考仍是界面截图，不是同规格双端导出的像素精度验收。
- 本机 macOS arm64 的私有运行时经过测试。不据此宣称 Windows/Linux、移动人物、多脸遮挡或侧脸已经达到同等效果。

## 美妆 UI 与数据语义

分类按剪映顺序保留：套装、口红、腮红、修容、卧蚕、眉毛、睫毛、眼线、眼影、美瞳、高光、雀斑。

- 分类为紧凑、可换行的 pill 标签；标准面板中为 5/5/2 排列，卡片为四列正方形、青色选中边框和“无”卡片。
- 分类没有素材时仍可查看，不偷偷跳到其他分类。
- 强度范围是 0–100。重置强度到 0 保留选中的卡片，但不运行对应效果；“无”才删除当前分类。
- 再次点同一张卡片不重置用户强度；切换分类不创建无意义的撤销项。
- 保留其他美妆分类和其他人脸的数据。修复了清除某个人脸最后一个分类时，旧 `makeup` 被对象展开重新带回来的问题。
- 不可用包禁用应用，但用户仍能清除保存的旧选择。键盘导航、输入提交/取消、指针取消和单次撤销边界均有测试。

### 封面修正

旧封面来自效果包内部 UV 纹理，甚至有透明的 lip mask，不能用作真正的素材卡封面。

新路径复用资源目录封面查询与 `jianying-image-cache`：按 ID/版本匹配，可信 ByteImg HTTPS 来源，校验图片格式和 768 KiB 大小上限，本机原子写入缓存，向渲染端只返回 data URL。缓存齐全后不再扫描目录或联网。私有目录的签名地址失效时，尝试同版本安装目录地址；失败显示占位图，不误用 UV 纹理。

封面下载只在面板检查时发生；逐帧 `render` 只解析本地效果包，不查封面目录、不下载图片。没有上传人物照片、项目或人脸信息；封面网络请求也不携带账户 cookie。

当前未确认剪映原生 `Cache/image` 的 URL 到文件名映射，所以没有伪造一个所谓“原缓存解码器”。封面建立的是 QCut 自己的私有缓存，不把供应商图片、效果包、Lua、模型或二进制提交到 Git。

本机主运行时已缓存 15/15 张封面；另外使用独立空目录 `covers-cold-cache/` 实测冷缓存解析，15 张都成功，缺失列表为空。完整编辑器链路还检查了实际图片解码，不只检查 URL 非空。

## E2E 发现并修复的问题

第一次大链路在“小翘鼻 50 + 柔和粉 50”的暂停画面上失败：1800×1100 缩到 1280×800 后，同一输入、参数、时间戳的画布哈希发生变化。单项成功不足以证明组合成功。

原因是下游美妆和新增拟合包在同一静止输入上重复推进原生拟合状态。将三个新鼻包、眉形包和美妆加入已有固定帧身份机制，按输入像素、参数、时间戳决定保持、继续或重建。

修复后完整链路通过：窗口缩放后像素稳定，保存退出再打开保持相同哈希。新增 provider 测试还验证运动输入继续渲染，反向寻帧/参数变化按原有规则重建，不把视频误冻结。

多脸型复测时发现测试夹具把两张竖幅真人设为方形画布。已改为读取原图宽高，固定宽 1080、按比例计算偶数高度，并同步检查画布和导出尺寸。旧的拉伸运行保留为诊断证据，不计入视觉验收。

## 仍然需要缩小的差距

1. 完整美妆素材目录、预设数量和下载管理仍远少于剪映，当前只有选定的 15 张卡片。
2. 配对图显示新增鼻/眉操作的作用区域总体相近，但鼻部对嘴部的连带形变和部分档位的局部强度仍不完全一致。需要同规格双端导出后，继续查拟合输入尺寸、关键点和阶段顺序，不凭截图调一个全局乘数。
3. 本轮只为六个新算子和一张口红卡新增剪映同值配对；其他标准五官虽跑了 QCut E2E，不能据此算剪映效果验收完成。
4. 此前多脸型脸部测试仍有 GAN 轮廓、部分颧骨的残差。本轮新增五官接入不能覆盖那个问题。
5. 仍要补多人物、侧脸、遮挡、低分辨率、连续运动视频、多分类美妆叠加与人体效果同时启用的长链路。
6. Windows/Linux 运行库与模型可用性、全新安装机的资源缺失恢复，需要独立验收；不能以本机私有缓存齐全替代发行版验证。
7. 分组仍采用 QCut 的折叠标题和生效指示点，而剪映使用分组复选框；本轮对齐了内容、顺序、分类和卡片布局，不宣称整个属性面板逐像素相同。
