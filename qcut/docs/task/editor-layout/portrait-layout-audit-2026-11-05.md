## 1. 高优先级：时间线工具栏被面板裁切

左右竖屏、属性优先、媒体优先布局都会压缩时间线宽度。工具栏没有相应折叠或滚动入口，右侧缩放、吸附、波纹编辑等可用控件落到面板之外。

实测工具栏宽度 / 内容宽度：

| 视口 | 默认布局 | 左/右竖屏 | 属性优先 | 媒体优先 |
| --- | --- | --- | --- | --- |
| 1440×900 | 1432 / 1432 | 846 / 1424 | 931 / 1424 | 996 / 1424 |
| 1280×800 | 1272 / 1424 | 750 / 1424 | 825 / 1424 | 884 / 1424 |
| 1920×1080 | 1912 / 1912 | 1134 / 1424 | 1247 / 1424 | 1332 / 1424 |

单位为 CSS px，面板宽度四舍五入。实际截图与 `document.elementFromPoint()` 均确认多个启用按钮的中心无法命中自身。1440 宽的左右竖屏布局中，有 11 个启用按钮的中心被遮挡；1920 宽仍有 6 个。

- 证据：`1440x900-vertical-preview.png`、`1920x1080-vertical-preview.png` 及对应 JSON。
- 代码：`apps/web/src/components/editor/timeline/timeline-toolbar.tsx:410` 的固定单行工具栏；三组内容在空间不足时没有容器断点或溢出菜单。
- 建议：按时间线容器宽度折叠次要工具，保留播放、主要剪辑和缩放入口。断点应针对面板，不能仅看整个窗口宽度。
- 验收：逐个布局验证缩放/吸附/波纹按钮可以鼠标命中；拖小面板后仍有明确可访问入口。

## 2. 中优先级：默认 ↔ 音频布局切换尺寸不同步

1440×900 下连续操作：

| 操作 | store 的时间线比例 | 工具栏顶部 y | 实际结果 |
| --- | --- | --- | --- |
| 默认布局 | 约 30% | 647 px | 正常 |
| 切换到音频创作 | 52% | 647 px | 画面仍是默认高度 |
| 手动重置音频预设 | 约 52% | 462 px | 音频预设高度此时生效 |
| 切回默认布局 | 约 30% | 462 px | 画面仍保留音频高度 |

- 证据：`switch-1-default.png` 至 `switch-4-default-return.png`，`measurements.json` 同时保留 store 与 DOM 尺寸。
- 原因：`apps/web/src/routes/editor.$project_id.lazy.tsx:299` 和下一行渲染相同的 `DefaultLayout` 组件；`apps/web/src/components/editor/panel-layouts.tsx:57` 仅随 `resetCounter` 重新计算初始尺寸，内部 panel group 的 key 也只包含该 counter。普通预设切换没有触发重新挂载或重算。
- 建议：按预设身份重新挂载对应布局，同时保持拖动过程中初始尺寸稳定；保留每个预设各自的自定义尺寸。
- 验收：默认→音频→默认，音频重置→默认，自定义拖动后往返切换，以及重新打开项目后的尺寸恢复。

## 3. 中优先级：窄预览区的全屏按钮被裁切

1280×800 的左右竖屏和媒体优先布局中，“进入全屏”按钮位于预览容器外，按钮中心命中测试失败。9:16 画布本身仍正常显示。

- 证据：`1280x800-vertical-preview-left.png`、`1280x800-media.png`。
- 代码：`apps/web/src/components/editor/preview-panel-components.tsx:569` 的单行 `PreviewToolbar`，多个工具组在窄面板下无法容纳；外层预览区裁切溢出内容。
- 建议：对预览容器设置紧凑模式，将低频控制收入菜单，保留播放和全屏按钮。
- 验收：拖小预览面板以及 1280 宽窗口下，完整显示播放、比例/缩放入口和全屏按钮。

## 4. 中优先级：1280 宽窗口顶栏内容重叠

使用正常长度项目名 `Export acceptance portrait`，1280 宽时项目名按钮实际宽 231 px，但左侧容器只有约 111–150 px，项目名溢出后与时长、版本/状态重叠。左右竖屏的 Layout 名称更长，使挤压更明显。

- 证据：`1280x800-default.png` 与 `1280x800-vertical-preview-left.png` 顶栏，JSON 中的 `headerChildren` / `headerName`。
- 代码：`apps/web/src/components/header-base.tsx:35` 允许左容器收缩，但项目按钮没有对应截断；右侧工具组在第 41 行固定 `shrink-0`。
- 建议：项目名设置真实可收缩的截断区域；紧凑窗口合并低频工具，优先保留项目菜单、Layout 和导出。
- 验收：1280 宽下长/短项目名、中文/英文、六种布局均无重叠。

## 正常表现与证据边界

- 左右竖屏预览是镜像布局，预览区确实更高；这个设计方向适合 9:16。
- 各截图中的画布宽高比保持 9:16，未发现本轮布局切换造成画面变形。
- 默认布局在 1440 和 1920 宽度下，受检查的时间线和预览控制未被裁切。
- 素材导航隐藏在“更多”菜单中的条目不计为缺陷；通用溢出扫描只用作线索，结论以截图与对应控制的命中测试为准。
- 本轮仅审查 macOS Electron、中文界面和上述固定视口。尚未覆盖 Windows、系统缩放、多显示器或手动拖动后的极限尺寸。
